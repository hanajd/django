# 合并报告规则说明

本文档对应实现代码：`utils/pdf_merge.py`、`apps/api/inspection_pdf_service.py`（`collect_report_merge_source_rows`、`build_report_merge_overlay`），以及与合并入口相关的视图/服务调用。合并入口函数为 **`merge_report_pdfs_header_toc_sections`**，叠印入口为 **`apply_merged_report_merge_overlay`**。

---

## 1. 总体结构

- **输入**：多份已生成的「报告」PDF 路径列表（至少 2 份），顺序即合并顺序；**第一份**的前 `header_page_count` 页（默认 **N=3**）作为全稿统一的「封面、声明、一、项目基本情况」版式底图。
- **输出**：单份合并 PDF 字节流；失败时返回错误信息字符串。
- **每份报告**：须能在 PDF 中定位到「**三、检测结果**」起始页；从该页起截取至「四、」或「附录」等下一主节之前，作为该份在合并稿中的一节；若某节拼接时首行重复「三、检测结果」标题，会尝试擦除重复行。

**物理页序（默认 N=3）**

| 物理页（1-based） | 内容 |
|------------------|------|
| 1 | 封面（来自首份 PDF 第 1 页） |
| 2 | 声明（首份第 2 页） |
| 3 | 一、项目基本情况（首份第 3 页） |
| 4 | **目录**（程序生成，非首份原页） |
| 5+ | 各份「三、检测结果」按勾选顺序拼接 |

**页眉**：除封面、声明外，合并结束后统一按固定几何重绘左上「报告编号」、右上「第 x 页/共 y 页」；目录页页码规则见代码内 `rewrite_merged_report_page_headers` 与 `_report_body_page_from_physical_1based` 等注释。

## 2. 叠印字典 `merge_overlay`

由 **`build_report_merge_overlay`**（`inspection_pdf_service.py`）调用 **`build_merged_report_overlay_fields`**（`pdf_merge.py`）生成，供 **`apply_merged_report_merge_overlay(doc, nh, merge_overlay)`** 消费。

### 2.1 字段一览

| 键 | 含义 |
|----|------|
| `merge_date_str` | 封面「报告日期」叠印文案（如 `2026年5月12日`） |
| `inspected_org` | 受检单位（与封面单位行、`cover_org_line` 同源） |
| `cover_org_line` | 封面「项目名称」格内**第一行**（受检单位） |
| `cover_report_title` | 封面「项目名称」格内**第二行**（合并报告名称，如 DSA、DR、CT 三台…） |
| `inspection_index_line` | 封面「受检编号」格：多份时如 `01、02、03` |
| `project_name_combined` | 基本情况表「项目名称」单行语义：**受检单位名称 + 合并报告名称**（与封面两行总语义一致） |
| `device_count_label` | 基本情况「受检设备台数」取值，如 `3 台` |
| `evaluation_body` | 「二、评价」正文两段（换行分隔），见下文缩进规则 |

### 2.2 溯源与受检单位（生成 overlay 时）

- **`collect_report_merge_source_rows`**：为每份库文件收集 `title_line`、`inspected_org_hint`、`path`、`submit`（若关联案件且解析到提交 JSON）等。
- **`_inspected_org_from_submit_row`**：从 `submit.hospitalInfo` 取值，**字段优先级**（先匹配到的非空串即采用）：`inspection2` → `inspection` → `inspectedUnit` → `inspectedOrganization` → `hospitalName` → `entityName` → `commissionedUnit`（多数模板受检单位在 `inspection2`）。
- 若仍无单位：对**每一行** `path` 依次调用 **`extract_cover_inspected_unit_fallback`**，从首份等 PDF 封面文本用正则匹配「受检单位：」「委托单位：」「申请单位：」等行首标签后内容。
- **合并报告名称**（`cover_report_title`）：由各份标题抽取设备类型（`extract_modality_abbr_from_title`，优先匹配 `pdf_merge.MERGED_REPORT_DEVICE_TYPE_LABELS` 中的大类，如动态DR、胃肠机、口腔CBCT 等），经 **`merged_cover_report_title_from_abbrs`** 生成（≤3 台为「动态DR、胃肠机、DSA3台设备质量控制检测」类句式，**台数用阿拉伯数字**；多于三台为前三种加「等 n 台设备质量控制检测」）。
- **评价句**中的设备短语：**`merged_device_phrase_for_evaluation`**，用于 `evaluation_body` 首段内「对{org}{dev_eval}…」。

## 3. 叠印执行 `apply_merged_report_merge_overlay`

### 3.1 调用时机

在 **`merge_report_pdfs_header_toc_sections`** 内：

1. 插入首份前 `nh` 页后，**第一次**调用 `apply_merged_report_merge_overlay`；
2. 插入目录、各节、**`rewrite_merged_report_page_headers`** 之后，**第二次**调用同一函数，避免页眉整带擦写与叠印顺序导致漏改或错位。

### 3.2 基本情况「项目名称」单行 `pfn` 的合成规则（与 overlay 的关系）

叠印前在**已插入、尚未二次破坏文本层**的文档上：

1. **`org_pdf_cell`**：若配置了 **`summary_inspected_org_value`** 固定框，则在第 `nh` 页（0-based 索引 `nh-1`）用 `get_text(clip=矩形)` 读取该框内印刷字，去掉行首「受检单位：」「单位名称：」「医疗机构：」等标签，空白折叠为单行。
2. **`org_for_pfn = (org_pdf_cell or cover_org_line/inspected_org).strip()`** — **表格内读到的单位名优先**。
3. **`pfn`**：若 `org_for_pfn` 与 `cover_report_title`（`crt`）均非空，则 **`pfn = org_for_pfn + crt`**；否则回退 `project_name_combined` 并在缺前缀时补 `org_for_pfn`。  
   **封面**仍只用 overlay 的 `org` / `crt` 两行逻辑，不强制改用 `org_pdf_cell`（单位格读取主要为基本情况单行服务）。

### 3.3 固定矩形叠印（`_MERGE_OVERLAY_FIXED_RECT_1BASED_XYWH`）

字典值为 **`(物理页码 1-based, x0, y0, width, height)`**，坐标系为 **PyMuPDF 页面坐标：原点左上，y 向下**。实现中转为 `fitz.Rect(x0, y0, x0+w, y0+h)`。

| 键 | 用途 |
|----|------|
| `cover_report_title` | 首页：合并报告名称（第二行），优先于此矩形叠印；未配置或页不匹配时回退几何分割下半格 |
| `summary_project_name` | 第 3 页：基本情况「项目名称」叠印区 |
| `summary_inspected_org_value` | 第 3 页：叠印**前**读取受检单位印刷字，参与 `pfn` 合成（见 3.2） |
| `summary_device_count` | 第 3 页：受检设备台数 |
| `summary_evaluation` | 第 3 页：「二、评价」正文 |

当 **第 `nh` 页（索引 `nh-1`）** 上 **`summary_project_name`、`summary_device_count`、`summary_evaluation` 三者均能解析到与当前页匹配的矩形**，且 `pfn`/`dcl`/`eva` 至少一项非空时，**该页三项全部采用固定框路径**（透明擦除 + 叠字），不再走按「项目名称」「受检设备台数」等搜字的动态测框逻辑。

**模板或纸张变更后**：必须按实测 PDF 重新标定上述元组，否则会出现偏移、压线或与表格外竖线干涉。

### 3.4 评价正文 `evaluation_body`

- 叠印前经 **`_merge_evaluation_overlay_text`**：对每一行去掉行首空白后，**仅当**该行以「**应委托方要求**」或「**所检设备的质量控制相关参数**」开头时，在行首增加 **两个全角空格**（`\u3000\u3000`）；其它行（如自动换行续行）不额外加段首缩进。
- 评价区擦除与书写：使用 **`_MERGE_EVAL_BOX_H_INSET_PT`（默认 3pt）** 对固定框/动态框做**左右内缩**，减轻 `apply_redactions` 吃掉表格外竖线；动态路径不再对整块评价区做统一几何左偏移，避免与上述「仅两处缩进」冲突。

### 3.5 封面「项目名称」两行

- 标签「项目名称」定位：优先 **`_merge_search_last_by_bottom`**，避免命中页眉等较上处的重复词。
- 取值带：在几何两行的 `band` 上，仅用字典行结果**扩展右边界**，**纵坐标锁回** `_merge_cover_project_name_value_band`，避免 `include_rect` 把竖向拉满导致中缝错位、第二行不显示。
- 报告名称行：若存在 **`cover_report_title`** 的固定矩形且当前为首页，则在该矩形内写 `crt`，否则用 **`_merge_cover_project_name_two_line_write_rects`** 的下半格。

### 3.6 其它合并后处理（同文件内）

- **`apply_merged_inspection_numbers_on_section_heads`**：各节「三、检测结果」块内，将「受检编号」行改为「（n）受检编号：nn」格式；每页成功改写后**立即结束**该页循环，避免文本层未更新导致重复叠画。
- **`apply_merged_quality_subheading_renumbers`**：第 2 份及以后将小节标题行首「**1.1**」「**1.2**」…改为「**n.1**」「**n.2**…」（与目录中 n.1 一致）；首份不修改。

## 4. 依赖与运维注意

- **PyMuPDF（`fitz`）** 为必需依赖；叠写字体与 **`htmlpdf_service`** 中宋体路径一致（见 `_merge_overlay_write_text_html_style`）。
- **目录水印**：环境变量 `MERGED_REPORT_WATERMARK_PNG` 或默认 `media/file_library/templates/merged_report_watermark.png`。
- **变更检查清单**：首份 PDF 版式、`header_page_count`、固定框常量、`hospitalInfo` 字段设计、案件与提交 JSON 是否关联（影响 `traced` 与 hint 文案）。
