# 检测业务后台管理系统说明（甲方版）

本文面向**业务管理人员、项目负责人与一线检测岗位**，介绍 Web 后台的主要能力、推荐操作顺序与常见概念，便于培训、验收与日常使用。文中不涉及程序实现细节；若与贵单位书面制度不一致，**以贵单位规定为准**。

系统内另提供分页的 **「后台系统使用说明」** 与 **「流程练习」**（在真实页面上按步骤操作，练习结束可清理本次新建数据），适合首次上手时配合阅读。

---

## 一、系统定位

本后台与**检测 App / 平板端**配套使用，承担以下职责：

| 职责 | 说明 |
|------|------|
| **项目与任务组织** | 按检测项目挂载标准检测项，明确「本项目做哪些检测」。 |
| **版式与资料管理** | 集中存放空白表、模板、现场记录、报告、附件等，按业务阶段分类。 |
| **流程与分工** | 登记各环节参与人（每岗可多人）；指定项目主要负责人；向参与人同步任务以支持并行作业。 |
| **任务下发** | 将项目任务同步给外业或 App 用户，使其在移动端看到待办。 |
| **成果归档** | 现场填报、审核通过后生成现场记录与正式报告 PDF，支持合并交付。 |

一句话概括：**在后台定好「项目—任务—版式—人员」，在 App 上完成现场填报与签字，在后台与文件库中形成可追溯的记录与报告。**

---

## 二、主要功能模块

| 模块 | 面向谁 | 做什么 |
|------|--------|--------|
| **项目工作台** | 项目负责人、管理员 | 选项目、挂任务、登记流程参与人、指定主要负责人、向参与人同步任务、查看提交状态。 |
| **任务模板库** | 模板维护人员 | 维护每种检测的版式绑定、默认仪器、试导出核对。 |
| **文件库** | 全体有权限用户 | 按分类管理模板、现场记录、报告、附件等文件；回收站恢复或彻底删除。 |
| **模板编辑器** | 版式维护人员 | 在 PDF 上划定填写区，保存坐标与规则，试填并导出 PDF。 |
| **文档识别**（若启用） | 资料整理人员 | 对待识别扫描件做结构化抽取，结果进入数据文件分类。 |
| **用户 / 角色 / 菜单** | 系统管理员 | 账号、岗位职责与菜单可见范围（一般业务人员无需进入）。 |

不同岗位看到的**左侧菜单可能不同**，这是按职责精简界面，并非功能缺失。

## 三、推荐工作流程

下列顺序适用于大多数新项目上线，可按单位实际情况微调。

```text
确定检测项目
    ↓
在项目工作台「任务与模板」中挂载检测任务
    ↓
（若有报告类任务）为报告勾选对应的现场记录来源任务
    ↓
在任务模板库绑定版式 PDF、数据文件与默认仪器
    ↓
在「分配」中指定项目主要负责人（每项目一名）
    ↓
在「分配」中向一名或多名参与人同步任务（检测员可多人并行）
    ↓
在「流程」中登记各环节参与人（校核、编制、审核、签发等；每岗可多人）
    ↓
外业在 App 填报、签字；各环节在流程中推进或退回
    ↓
形成现场记录与报告 PDF（文件库对应分类）；必要时合并多份报告对外交付
```

**要点：**

- 许多列表与按钮只对**当前选中的项目**生效，请先在工作台左侧点选项目。
- 仅在任务模板库中「新建」模板，**不会**自动被任何项目使用，必须回到项目工作台**勾选进本项目**。
- 将任务挂到项目时，系统会**自动同步**该任务已绑定的模板类文件到项目，一般无需在项目里逐条手工关联版式文件。

## 四、项目工作台（核心入口）

项目工作台是围绕**单个检测项目**开展配置的中心，常用页签如下。

| 页签 | 用途 |
|------|------|
| **概览** | 查看本项目任务数、分配人数、提交数及推荐工作流提示。 |
| **任务与模板** | 勾选本项目包含的检测任务；为**报告类任务**指定汇总哪些**现场记录类任务**的数据来源。 |
| **流程** | 登记本项目五个标准环节的**参与人**（用于流程展示与签字归属）；同一岗位可多人；查看关联案件当前环节。 |
| **文件** | 按分类将文件库中的记录加入或移出本项目（**部分演示/业务账号不显示此项**，版式随任务挂载即可）。 |
| **分配** | 指定**项目主要负责人**（每项目一名）；并向**一名或多名**参与人同步任务，是外业并行检测的主要入口。 |
| **提交** | 查看与本项目相关的检测提交（任务编号）及状态，必要时将「已提交」回退为待处理（按权限）。 |

### 4.1 任务与模板

- **加入项目 / 从项目移除**：勾选标准检测任务后保存，声明「本项目包含哪些检测项」。
- **报告与现场记录关联**：选择某一报告任务后，勾选作为数据来源的现场记录任务，保存关联。这样生成报告时能按规则汇总对应现场记录。

### 4.2 流程与成员

标准环节顺序为：

**现场填写（检测员）→ 现场校核（校核员）→ 报告编制（编制人）→ 报告审核（审核人）→ 授权签发（授权签字人）→ 已签发**

企业实践中需区分三类「人员配置」，不要混为一谈：

| 配置方式 | 解决什么问题 | 是否支持多人 |
|----------|--------------|--------------|
| **「分配」页的项目主要负责人** | 谁对本项目工作台负总责；拥有本项目内的完整配置与分配权限 | **否**。每项目指定**一名**主要负责人 |
| **「分配」页的任务同步** | 谁能在 App 看到本项目、填报哪些检测任务；外业并行作业 | **是**。同一项目可向多名检测员（及其他 App 用户）同时同步任务 |
| **「流程」页的岗位参与人** | 各环节在流程中的参与人、签字栏归属、工作台展示 | **是**。校核、编制、审核、签发等岗位均可登记**多名**参与人 |

**说明：**

- **项目主要负责人**在「分配」页指定；指定后系统会为其自动同步本项目全部任务模板，并赋予该项目工作台内的完整操作权限。
- **多名检测员同时检测**是常态：在「分配」中分别把任务同步给各检测员即可；每人用自己的账号在 App 填报，形成各自的提交与现场记录。
- **「流程」页**用于登记各环节参与人；添加参与人**不会**替换同岗位其他人。检测员、校核员等岗位均可多人同时在岗。
- **审核人、授权签字人**等职能岗位：除可在某项目的「流程」中登记参与人外，其账号还可通过**全局角色**配置为「跨项目」处理——在未开启「仅本人数据」时，可查看并处理**所有活跃项目**中待审核、待签发的报告（适合质控科室、授权签字人等集中履职场景）。
- 同一人可兼任多个流程岗位（小型项目或演示环境常见）；是否允许兼任由单位制度与管理员在角色管理中把握。
- 签发日期以终审（授权签发）环节为准。

### 4.3 分配

- **项目主要负责人**：具备分配权限的账号可为项目指定**一名**主要负责人；指定后其拥有本项目工作台内的完整配置与分配权限。
- **向参与人同步任务**：具备分配权限的账号可向**多名** App 侧用户下发同一项目的任务（检测员并行即由此实现）。
- 仅负责本人项目的业务账号：通常只能**向本人账号**同步任务，用于体验完整流程。
- 被指定或同步任务后，对方须用**自己的账号**登录 App，并在可见项目中进入同一项目。
- 向用户同步任务时，系统会按该用户的全局岗位类型，尝试将其加入流程中的对应岗位（若尚未登记）；**不会**因新增一名检测员而挤掉其他已分配检测员的任务。

## 五、任务模板库

**何时需要维护：** 新增检测类型、更换空白表版式、调整默认仪器清单、核对 PDF 版式是否正确。

| 步骤 | 说明 |
|------|------|
| 新建模板 | 填写名称，选择用于**现场记录**还是**报告**类成果。 |
| 勾回项目 | 回到项目工作台，将新任务**加入本项目**并保存。 |
| 绑定版式与仪器 | 在任务详情中关联文件库里的 PDF、JSON 等，并设置常用设备。 |
| 试导出 | 选择已有数据的项目试生成 PDF，检查版式与字段；若提示缺数据，需先完成现场填报。 |

## 六、文件库

打开文件库后，请关注**顶部分类标签**，把资料放进正确「柜子」，后续填报、导出、合并才能被系统正确引用。

| 分类 | 典型用途 |
|------|----------|
| **模板** | 空白或半空白 PDF、坐标 JSON、前端规则等；可点「编辑模板」进入模板编辑器。 |
| **待识别文件** | 待做文档识别的扫描件、图片（若单位启用识别流程）。 |
| **数据文件** | 结构化 JSON 等，供填表、导出使用。 |
| **现场记录** | 现场工作形成的记录类 PDF 等成果。 |
| **报告** | 对外正式报告 PDF；可多选后**合并**成一份总报告（若单位启用）。 |
| **附件** | 补充照片、说明文档等，避免与正式记录、报告混淆。 |
| **检测提交** | 由 App 或业务系统自动写入，一般不支持手工上传。 |
| **回收站** | 已删除文件的暂存区，约保留 30 天；可**批量恢复**或**批量彻底删除**。 |

**回收站说明：** 删除文件时先移入回收站，在保留期内可恢复；超期后由系统自动清理。批量操作与单条操作的权限规则一致（默认仅能处理本人上传的文件，管理员可处理可见范围内的他人文件）。

**数据范围：** 若账号开启「仅本人数据」，列表以本人上传或已分配项目关联的文件为主；是否可上传、下载、删除仍由角色权限决定。

## 七、模板编辑器（简要）

**入口：** 文件库 → **模板** 分类 → 目标 PDF 行的「编辑模板」。

**典型顺序：** 载入已有 JSON 版式（或按红字/手动画框）→ 在左侧核对字段名称 → 保存坐标模板 → 试填后选择保存到「现场记录」或「报告」→ 导出已填写 PDF。

详细按钮说明见系统内 **「后台系统使用说明 → 模板编辑器」** 专篇。

## 八、现场记录与报告（业务关系）

理解下面几条，有助于解释「为什么一个项目里有多份报告、一份报告又合多份现场记录」：

| 概念 | 说明 |
|------|------|
| **项目** | 管理范围与资料归属；一个项目下可有多台设备、多条检测线。 |
| **现场记录** | 贴近单次或单阶段实测过程的留痕（读数、工况、签字等）。 |
| **报告** | 对外正式结论，一般在现场记录与数据审核通过后编制。 |
| **一份报告 ↔ 多份现场记录** | 同一检测对象可能有多张表、多阶段记录，报告常**汇总**多份现场记录。 |
| **一个项目 ↔ 多份报告** | 多台设备或单元各自出具报告，均归在同一项目下。 |
| **报告合并** | 多科室或对外交付只需部分报告时，可在报告分类中多选后合并。 |

**记忆口诀：** 项目管范围；现场记录管过程；报告管结论；多设备则多报告；单报告常合多份现场记录；多科室则常要选用与合并。

## 九、权限体系（企业工作流视角）

检测业务的权限并非「一个开关」，而是**全局角色**与**项目内配置**叠加，以兼顾「多人并行现场作业」与「跨项目质控、签发」两类诉求。

### 9.1 四层结构（由外到内）

```text
┌─────────────────────────────────────────────────────────┐
│  ① 账号角色（全系统）                                     │
│     菜单、上传/下载/删除、能否向他人分配任务、数据是否「仅本人」   │
├─────────────────────────────────────────────────────────┤
│  ② 项目主要负责人（每项目一名）                             │
│     本项目工作台内的完整配置与分配权限；自动同步全部任务模板      │
├─────────────────────────────────────────────────────────┤
│  ③ 项目内任务同步                                         │
│     谁在本项目有活干；支持多名检测员并行                    │
├─────────────────────────────────────────────────────────┤
│  ④ 项目内流程岗位参与人                                   │
│     校核 / 编制 / 审核 / 签发等环节的参与人；每岗可多人       │
└─────────────────────────────────────────────────────────┘
```

管理员在「角色管理」中维护第 ① 层；具备分配权的负责人在「项目工作台」维护第 ②、③、④ 层。

### 9.2 全局角色：几类典型账号

| 类型 | 典型岗位 | 数据范围（默认倾向） | 典型能力 |
|------|----------|----------------------|----------|
| **系统管理** | 超级管理员、管理员 | 全单位文件与项目 | 用户/角色/菜单、向他人分配任务、项目配置 |
| **现场作业** | 检测员、校核员 | 多为「仅本人数据」+ 已分配项目 | App 填报、现场记录、本岗签字与退回 |
| **报告编制** | 编制人 | 多为「仅本人数据」+ 已分配项目 | 编制报告、修改被退回的报告 |
| **跨项目质控** | 审核人 | **默认可见全部项目**相关现场记录与报告 | 报告审核、退回；可不依赖单项目任务分配 |
| **跨项目签发** | 授权签字人 | **默认可见全部项目** | 终审签发、写入签发日期；可不依赖单项目任务分配 |
| **版式维护** | 模板编辑、模板测试 | 按角色配置（可全库或仅本人） | 任务模板库、模板编辑器、试导出 |

同一登录账号只绑定**一个**全局角色；细项权限可在「编辑角色」中按**基础操作 / 数据范围 / 流程与业务**三类微调。

### 9.3 「仅本人数据」与跨项目权限

| 设置 | 含义 | 常见适用对象 |
|------|------|--------------|
| **开启「仅本人数据」** | 文件库以本人上传或**已通过任务分配关联**的项目资料为主 | 外业检测员、编制人等 |
| **关闭「仅本人数据」** | 可按角色查看更广范围（如**全部活跃项目**的待审报告、待签报告） | 审核人、授权签字人（默认即关闭） |
| **具备「分配文件库任务」** | 可指定项目主要负责人、向参与人同步任务、维护流程成员等 | 管理员、部分项目负责人 |

因此：**高权限的审核人 / 授权签字人**不必在每个项目里逐一「分配任务」，仍可在职责范围内处理多项目的审核与签发；是否如此，取决于管理员是否为该角色关闭「仅本人数据」并保留相应菜单与流程权限。

### 9.4 五类流程岗位（职责摘要）

| 岗位 | 主要职责 | 与「多人」的关系 |
|------|----------|------------------|
| **检测员** | 现场填报、上传现场记录、本岗签字 | **多人并行**：通过「分配」向多名检测员同步任务；「流程」中也可登记多名检测员 |
| **校核员** | 校核现场记录，通过或退回检测员 | 「流程」中可登记**多名**校核员 |
| **编制人** | 依据校核通过的记录编制报告 | 「流程」中可登记**多名**编制人 |
| **审核人** | 审核报告，通过或退回 | 流程参与人 + 可配置为**跨项目**审核权限 |
| **授权签字人** | 终审签发，写入签发日期 | 流程参与人 + 可配置为**跨项目**签发权限 |

**系统管理员**负责账号与角色，一般不直接参与现场填报，除非另行赋予业务岗位并参与分配。

### 9.5 管理员配置时建议对照

| 业务诉求 | 建议配置 |
|----------|----------|
| 三个检测员同时测同一项目 | 在「分配」中分别同步任务给三名检测员；在「流程」中可登记多名检测员参与人 |
| 质控科审核所有项目报告 | 审核人角色关闭「仅本人数据」；按需保留文件库与流程操作权限 |
| 授权签字人统签多项目 | 授权签字人角色关闭「仅本人数据」；在各单位项目流程中登记签字人或使用跨项目履职 |
| 外业只能看自己的活 | 检测员角色开启「仅本人数据」，且仅通过「分配」获得项目任务 |
| 项目负责人只管某一个项目 | 指定其为该项目**主要负责人**，或赋予全局分配权；在对应项目内维护任务、流程与分配 |

## 十、与检测 App 的配合

| 后台完成 | App 侧体现 |
|----------|------------|
| 项目挂载任务、向多人同步 | 各检测员登录后看到同一项目及各自待办检测项 |
| 任务绑定版式与仪器 | 填报界面加载对应表单与默认设备 |
| 流程岗位参与人登记 | 各环节签字、推进与退回与岗位角色相匹配 |
| 审核人/签字人跨项目角色 | 可在多个项目的待审、待签队列中履职（无需逐项目分配） |
| 提交写入检测提交分类 | 后台可在项目工作台「提交」页查看任务编号与状态 |
| 审核通过、触发导出 | 现场记录 / 报告 PDF 进入文件库对应分类 |

## 十一、新手学习建议

1. 阅读系统内 **「后台系统使用说明」** 总览，建立整体图景。  
2. 点击 **「开始流程练习」**，在真实页面完成：选项目 → 挂任务 → 维护模板 → 分配（练习结束可清理本次新建数据）。  
3. 按岗位只精读与自己相关的篇章（项目工作台、文件库、任务模板库、现场记录与报告等）。  
4. 遇问题先查 **「常见情况与排查」**：是否已选项目、是否已挂任务并保存、是否选对文件库分类、是否具备对应菜单权限。

## 十二、常见问题（自查）

| 现象 | 建议先检查 |
|------|------------|
| 列表为空 | 是否已在项目工作台**选中项目**；任务是否已勾选进项目并保存；是否已有填报或上传。 |
| 按钮灰色 | 阅读页顶或按钮旁说明；常见为未选项目、未勾选文件、权限不足或前序步骤未完成。 |
| 导出 PDF 提示缺数据 | 当前项目下尚无对应填报或现场记录，需先完成 App 填报或数据登记。 |
| 看不到某个菜单 | 由角色控制；需扩展权限请联系单位管理员。 |
| 分配后对方仍无任务 | 是否选对项目；对方是否被分配；是否使用本人账号登录 App。 |
| 只能加一名检测员？ | 检测员人数在「**分配**」页向参与人同步任务即可扩展；「**流程**」页也可登记多名同岗参与人，并非每岗限一人。 |
| 审核人看不到某项目 | 是否开启「仅本人数据」；跨项目审核需该角色关闭此项；或是否需在项目中登记流程参与人。 |
| 回收站无法操作他人文件 | 默认仅能恢复/删除本人删除的项；需管理员处理他人回收项。 |

## 十三、权限与数据安全（业务视角）

- **角色（第 ① 层）**决定菜单、文件操作权、能否向他人分配任务，以及默认数据范围（是否「仅本人数据」）。  
- **项目主要负责人（第 ② 层）**每项目一名，拥有该项目工作台内的完整配置与分配权限。  
- **任务同步（第 ③ 层）**决定谁参与某项目的现场作业；**支持多人并行**，是检测员扩编的主要手段。  
- **流程岗位参与人（第 ④ 层）**为校核、编制、审核、签发等环节登记参与人；**每岗可多人**。  
- **审核人 / 授权签字人**在角色配置得当的情况下，可对**多个项目**履行审核或签发，无需在每个项目重复分配。  
- **回收站**提供误删缓冲；彻底删除不可恢复，批量操作前请确认勾选内容。  

具体账号能力以贵单位管理员在「用户管理」「角色管理」中的配置为准；若现场人数、质控范围与上文不一致，以实际角色勾选结果为准。
