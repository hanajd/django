# 勾选框条件公式实现说明

> 整理范围：模板编辑器中与「勾选框触发条件公式」相关的实现。  
> 产品约定（你此前要求）：**判断条件里只填对应勾选框的 `pdfFieldId`（如 `f588`）**；该勾选框被勾选后，自动命中并使用对应 `expression`。

相关代码与文档：

| 位置 | 作用 |
|------|------|
| `htmlpdf/templates/index.html` | 编辑器：条件公式 / 条件判定 / 报告条件映射 UI |
| `utils/conditional_field_rules.py` | 规则规范化、编译 `if(...)`、按条件选公式 |
| `utils/dynamic_form_expression.py` | 表达式求值、`_to_bool`、`if(c,a,b)` |
| `apps/core/htmlpdf_report_mapping_service.py` | 报告映射 `valueCases` 简写与布尔强制转换 |
| `docs/json公式说明.md` §3 | 条件公式通用约定 |
| `docs/条件公式与前端type约定.md` | 前端 `type: computed` 与匹配策略 |

## 1. 产品约定（目标行为）

在**计算栏位**的条件公式（`formulaRules`）中：

1. 「判断条件」只填勾选框的 **`pdfFieldId`**，例如 `f588`（不必写 `f588==true`）。
2. 现场该勾选框为**已勾选 / 真**时，本条规则命中，使用本条「公式」`expression`。
3. 未勾选 / 假时，本条不命中，继续试下一条；全部未命中则走兜底 `fieldExpression` 或人工选择逻辑（见 §3.2）。

示例（库模板 / 前端 JSON）：

```json
{
  "pdfFieldId": "f200",
  "type": "computed",
  "formulaRules": [
    {
      "id": "rule_when_check_a",
      "label": "勾选性能项 A 时",
      "condition": "f588",
      "expression": "avg(f10,f11,f12)"
    },
    {
      "id": "rule_when_check_b",
      "label": "勾选性能项 B 时",
      "condition": "f505",
      "expression": "min(f20,f21)~max(f20,f21)"
    }
  ]
}
```

语义：`f588` 勾选 → 用第一条公式；否则若 `f505` 勾选 → 用第二条。

## 2. 编辑器里实际有三条相关能力

不要把三者混为一谈；**只有第 1 条才是「条件公式 + 只填 pdfFieldId」**。

### 2.1 条件公式（`formulaRules`）——计算字段

| 项 | 现状 |
|----|------|
| 入口 | 侧栏「公式/判定」→ 非勾选框栏位的「条件公式」列表 |
| 规则结构 | `id` / `label` / `condition` / `expression`（四字段） |
| 判断条件占位 | 默认：`例：f12>=f13；留空则无需条件 / 需现场人工选择` |
| 是否对裸 `f588` 做简写展开 | **否**。输入原样写入 `condition`，**不会**自动改成 `f588==true` |
| 导出 | 有自动条件时编译为嵌套 `if(cond, expr, …)` 写入 `formula` / `fieldExpression` |

编辑器组件：`createConditionalRulesEditor`（`index.html`）。

匹配策略（文档约定）：

- `condition` 非空 + `expression` 非空 → **自动按序匹配**
- 多条且 `condition` 皆空 → **现场人工选择**
- 仅一条且 `condition` 空 → 当作默认公式自动算

### 2.2 条件判定（`judgmentRuleSets`）——合格/不合格标准切换

用于「同一检测类型下，按其它栏位（常为勾选框）切换判定式」。

| 场景 | 条件占位示例 |
|------|----------------|
| 勾选框自身的「条件判定」折叠区 | `例：f588==true、f505==false` |
| 普通数值栏位判定块 | `例：f588、f588==true、f505` |

说明文案已暗示可用裸 `pdfFieldId`，但**同样没有**把裸 `f588` 规范化为 `f588==true` 的保存逻辑。

勾选框**自身**的普通合格判定仍是填 `True` / `False`（勾选合格 / 勾选不合格），与「用别的勾选框当条件去切换公式」不是同一件事。

### 2.3 报告映射条件（`valueCases`）——勾选 → 报告文本

这是**报告模板映射**专用简写，**不是**现场计算 `formulaRules`：

| 编辑器填写 | 运行时展开 |
|------------|------------|
| `{1}` | `_s1 == true`（来源 1 勾选/真） |
| `!{1}` / `not {1}` / `非{1}` | `_s1 == false` |
| `{2}>=10` 等 | 仅替换 `{slot}` 为安全变量名 |

实现：

- 前端：`preprocessMappingCaseConditionClient`
- 后端：`_normalize_mapping_case_condition` + `_coerce_mapping_case_operand`（把 `✓`/`true`/`是` 等收成布尔）

命中判定比计算侧宽松：`matched is True` **或** 其它真值均算命中。

## 3. 运行时：裸 `pdfFieldId` 如何被当成「已勾选」

### 3.1 编译路径（导出后的 `if(...)`）

`compile_conditional_expression` 会把：

```text
condition: "f588", expression: "avg(f10,f11)"
```

编成：

```text
if(f588, avg(f10,f11), …)
```

`dynamic_form_expression` 里 `if` / `and` / `or` / 三元均走 **`_to_bool`**：

- `True` / 非 0 数字 → 真
- 字符串：空 / `false` / `0` / `no` / `off` → 假；**其余非空串（含 `true`、`✓`）→ 真**
- 因此：**走编译后的 `fieldExpression`/`formula` 时，裸 `f588` 对常见勾选存值基本可用**

### 3.2 规则逐条解析路径（`resolve_field_formula_for_eval`）

当栏位**没有**现成的 `fieldExpression`/`formula`、只能按 `formulaRules` 逐条试条件时：

```python
if eval_computed_formula(cond, vm) is True:
    return expr
```

这里用的是 **`is True`（严格布尔真）**，不是 `_to_bool`：

| `dynamicData[f588]` 实际值 | 裸条件 `f588` 求值结果 | `is True`？ | 是否算命中 |
|---------------------------|------------------------|-------------|------------|
| Python / JSON 布尔 `true` | `True` | 是 | 命中 |
| 字符串 `"true"` / `"✓"` / `"是"` | 原字符串 | **否** | **不命中** |
| 数字 `1` | `1` | **否** | **不命中** |
| `false` / `0` / `""` | 假值 | 否 | 不命中 |

未命中时会退回「第一条有 expression 的规则」作 fallback，**可能掩盖「条件其实没匹配上」**。

对比：报告映射对槽位值做了 `_coerce_mapping_case_operand`，再求 `== true`，并对命中做了真值放宽。

### 3.3 显式写法 `f588==true`

- 与布尔 `True`、整数 `1` 比较通常为真。
- 与字符串 `"true"`、`"✓"` 比较在表达式引擎里为**假**（除非先做与映射侧同类的布尔强制转换——**计算侧目前没有**）。

因此更稳妥的编辑习惯（在计算侧未补齐简写规范化之前）：

- 优先保证导出后存在编译好的 `if(f588, …)`（有自动条件时 `apply_formula_rules_to_field_dict` 会写）；或
- 条件写 `f588==true`，且确保运行态把勾选值规范成布尔 / `1`（Flutter / 提交 JSON 侧）。

## 4. 与产品约定的对照（结论）

| 约定点 | 当前实现 |
|--------|----------|
| 编辑器只填 `pdfFieldId` | **允许**：原样保存；**无**像映射 `{1}` 那样自动展开为 `== true` |
| 勾选后自动调用对应公式 | **设计支持**（非空 `condition` → 自动匹配）；导出编译的 `if(f588,…)` + `_to_bool` 路径较符合预期 |
| 全链路稳定识别「已勾选」 | **部分缺口**：逐条 `is True`、字符串勾选值、未做映射侧那套 coerce |
| UI 引导「只填 id」 | **弱**：公式区占位仍偏 `f12>=f13`；判定区文案已出现 `f588` / `f588==true` |

报告映射侧「只填 `{1}`」已按你的要求做完简写；**现场条件公式侧「只填 `f588`」尚未做到同等程度的规范化与取值强制转换**。

## 5. 配置操作备忘（按当前编辑器）

### 5.1 计算栏位：勾选框触发不同公式

1. 目标栏位设为可计算（导出须 `type: "computed"`）。
2. 「公式/判定」→ 添加公式。
3. **判断条件**填勾选框 id：`f588`（或显式 `f588==true`）。
4. **公式**填表达式：`avg(f10,f11,f12)` 等。
5. 需要多选一时，再加几条，每条对应不同勾选框 id。
6. 保存坐标 / 导出前端 JSON 后确认：
   - `formulaRules` 中仍有各条 `condition`；
   - 通常还有编译后的 `formula` / `fieldExpression`：`if(f588, …, if(f505, …, ""))`。

### 5.2 报告栏位：勾选映射成文案

1. 映射面板点选现场勾选框作为来源 `{1}`。
2. 条件映射填 `{1}` → 回填文本；未勾选需文案时再加 `!{1}`。
3. 与 §5.1 **不是同一套字段**（`valueCases` vs `formulaRules`）。

### 5.3 判定标准随勾选切换

展开「条件判定」：条件填 `f588` 或 `f588==true`，判定式填数值标准或勾选框用的 `True`/`False`。

## 6. 建议后续补齐（若要严格对齐「只填 pdfFieldId」）

不必改产品语义，只需把计算侧对齐映射侧的完成度：

1. **保存/导出规范化**：整段 `condition` 若匹配 `^f\d+$`（可选 `!f\d+`），展开为 `fN == true` / `fN == false`（与 `{1}` 对称）。
2. **命中判定统一**：`resolve_field_formula_for_eval` 对条件结果使用 `_to_bool`（或与 mapping 相同的 coerce + `is True`），避免字符串勾选值漏匹配。
3. **编辑器占位与 hint**：条件公式区写明「勾选框条件可只填 `f588`」。
4. **与 Flutter 对齐**：确认现场端对 `condition: "f588"` 与 `f588==true` 均按布尔勾选语义求值，并统一 `dynamicData` 中勾选值的类型。

---

## 7. 一句话摘要

- **你要的能力**：条件公式的 `condition` = 勾选框 `pdfFieldId`，勾选即自动用该条公式。  
- **编辑器**：可以这么填并保存，但**没有**像报告映射 `{1}` 那样的简写展开。  
- **导出编译的 `if(f…)`**：靠 `_to_bool`，对常见勾选字符串较友好。  
- **未编译、逐条 `is True` 的路径**：对非严格布尔的勾选值不稳，与约定仍有差距。
