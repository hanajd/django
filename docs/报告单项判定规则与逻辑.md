# 报告「单项判定」规则与逻辑说明

本文档整理系统中**质量控制检测报告**里「单项判定」列（合格 / 不合格）的**数据来源、计算顺序与数值规则**，对应实现主要在：

- `apps/api/inspection_report_make.py`（回填管线、判定标准解析、测量值配对）
- `utils/verdict_from_criterion.py`（由「判定标准」+「检测结果」数值推断合格性）

与 **HTML/PDF 模板划框时字段命名**（`{前缀}_单项判定`）相关的规则见仓库内 `HTMLPDF_AUTO_RED_BOX_RULES.md` 第 3～6 节。

---

## 1. 总体原则

0. **动态表单 `verdict.rule`（可选）**  
   若模板 steps 将 PDF 域与 `type: "verdict"` 绑定并配置了布尔表达式 `rule`，报告回填时 **优先按表达式** 得到合格/不合格（`passLabel` / `failLabel`）；表达式无法求值时再回退到下述「判定标准 + 测量值」逻辑。详见 `docs/动态表单后端对齐与前端配合说明.md`。

1. **单项判定格不直接吃现场 JSON 的原始文本**  
   字段若被识别为「单项判定」语义（见 `_is_single_item_verdict_text_field`，含 `type: "verdict"` 或带 `rule`），首轮 `_pick_value_for_field` 会**强制返回空字符串**，避免把占位符名或无关字符串写进报告。

2. **第二遍专门推算**  
   首轮遍历把所有普通文本、检测条件、检测结果等填完后，再对「单项判定」字段调用 `_auto_verdict_text_if_applicable`，用**判定标准 + 同行测量值**生成「合格」或「不合格」。

3. **无法可靠解析时保留兜底**  
   若缺少判定标准、测量值非数字、标准句式无法解析，则尽量保留 `submitPath` 等路径上已有的「合格/不合格」人工值，否则保留首轮结果（多为空）。

---

## 2. 回填两阶段（代码顺序）

实现位置：`_fill_template_fields_with_submit_enhanced`（`inspection_report_make.py`）。

| 阶段 | 行为 |
|------|------|
| 第一轮 | 遍历 `template_fields`：对 `_is_single_item_verdict_text_field` 为真的字段，`content` 置为 `""`；其它字段正常 `_pick_value_for_field` 等。 |
| 第二轮 | 再次遍历，仅处理单项判定字段：`field["content"] = _auto_verdict_text_if_applicable(field, 当前 content)`。 |

说明：注释中写「单项判定第二遍推算」即指上述第二轮。

---

## 3. 判定标准文本从哪来（`_get_judgment_criterion_text`）

按**优先级**依次尝试，命中即返回：

1. **模板字段自带**  
   `judgmentCriterionText`、`judgmentCriterion`、`criterionText`、或字段键名含「判定标准」且值非空。

2. **矩阵表（`layout=matrixTable`）**  
   `_matrix_criterion_text_for_verdict_pdf_field`：按表头找到「判定标准」列，根据「序号/行序号」列的**锚点行**（含合并行规则），把**单项判定所在物理行**映射到应使用的那一行上的判定标准单元格文案。

3. **占位符本身像标准句**  
   `originalPlaceholder` / `placeholder` 经 `_placeholder_text_looks_like_criterion` 判断为限值类描述时，直接作为标准。

4. **从 `value_mapping` 按单项判定键推导**  
   - 术者位防护区特殊逻辑：`_shield_zone_criterion_text_for_verdict_field`（同行 `…_判定标准` 或同体位身份下的其它行标准）。  
   - 否则：`_fuzzy_criterion_text_for_verdict_key` 模糊匹配。  
   - 再按「单项判定」键去掉 `_单项判定` 后的前缀链 `_verdict_row_bases_for_peer_match`，依次尝试 `{base}_判定标准`、`{base}_验收标准`、`{base}_限值` 等键在映射中的值。

若仍无标准，`_auto_verdict_text_if_applicable` 会尝试仅用 `submitPath` 取「合格/不合格」作为兜底。

---

## 4. 测量值从哪来（与单项判定行的对应关系）

对单项判定字段，在得到 `vkey`（含「单项判定」的候选键）后，按顺序尝试得到**一行测量文本** `measured`：

1. **`report_template_steps` 中的 pdfFieldId 顺序**  
   `_peer_result_pdf_field_id_for_verdict`：从当前「单项判定」控件在 steps 文档序中**向前**找最近一个 label 为「检测结果」「计算结果」「报出值」的控件，用其 `pdfFieldId` 在已填好的 `template_fields` 里取 `content`，或在 `value_mapping` 里取映射值。

2. **语义占位键候选**  
   `_verdict_measurement_placeholder_key_candidates`：由 `…_单项判定` 得到前缀 `base`，生成如 `{base}_检测结果`、`{base}_计算结果`、`{base}_报出值`、`{base}_检测值` 及无下划线变体等，在模板字段与 `value_mapping` 中查找。

3. **相似度匹配**  
   `_pick_qc_condition_result_by_similarity`（在仍无值时，用最长前缀等）。

4. **模糊测量**  
   `_fuzzy_measured_text_for_verdict`：在 `value_mapping` 里按与单项判定前缀的相似度选取带 `_检测结果` / `_计算结果` / `_报出值` / `_检测值` 后缀的键（**排除**含「判定标准」「单项判定」的键；术者位多行有专门限制，避免串格）。

**早退与保护**：

- 若测量文本等于某个占位键本身（防把键名当值），则放弃自动判定。  
- 若已是「合格」「不合格」，则直接采用。  
- 若测量文本看起来像**判定标准句**（`_placeholder_text_looks_like_criterion`），则不覆盖。  
- 若 `parse_first_number(measured)` 为 `None`（无法抽出数字），则不调用数值引擎（避免把纯文字当数）。

**特殊**：`joined_for_cond` 中含「透视防护区」且「术者位」时，`_report_merge_condition_result_text` 对检测条件/结果合并有专门分支，避免误拟合（与单项判定共用同一套行上下文）。

## 5. 数值判定引擎（`verdict_from_criterion.py`）

核心入口：`verdict_from_measurement(measured: str, criterion: str) -> Optional[str]`

- 先对标准串做 **NFKC、全角数字转半角、括号与比较符归一**（`normalize_criterion_text`）。  
- 从 `measured` 中取**第一个可解析浮点数**（`parse_first_number`）。  
- 若标准中含 **「且」「并且」「；」** 等，拆成多段，**每段都要满足**才为合格（`all`）；任一段无法解析则返回 `None`。

### 5.1 支持的标准句式（单段 `_eval_simple`）

| 类型 | 说明 |
|------|------|
| **对称允差** | `n±m`、`n ± m`、`n+/-m`：判定 `|测量值 - n| ≤ m`。 |
| **区间** | 两数字间为 `～`、`~`、`至`、`到`、连字符（且不含 `±`）：测量值落在闭区间内（含端点容差）。 |
| **≤ 上界** | `≤`、`<=`、`≦`、`不超过`、`不大于`、`小于等于`、`小于或等于` 等 + 数值。 |
| **≥ 下界** | `≥`、`>=`、`≧`、`不低于`、`不小于`、`大于等于`、`大于或等于` 等 + 数值。 |
| **严格 <** | `<`、`＜`（非 `<=`）、或「小于」且非「小于等于」：测量值 **<** 界限。 |
| **严格 >** | `>`、`＞`（非 `>=`）、或「大于」且非「大于等于」：测量值 **>** 界限。 |

比较时使用微小 epsilon（`1e-9`）减少浮点误差。

### 5.2 返回值

- 可完整解析且逻辑成立 → `"合格"` 或 `"不合格"`。  
- 任一必要环节缺失或无法解析 → `None`（由 `inspection_report_make` 再走 submitPath 等兜底）。

## 6. `value_mapping` 中与单项判定相关的注入（补缺判定标准）

在 `_prepare_backfill_value_mapping` 中，在构建现场与模板映射之后，会**仅对空键**写入缺省判定标准，供上节逻辑使用：

| 函数 | 作用 |
|------|------|
| `_inject_verdict_criteria_from_form_constants` | 从 `formSchema.constants` 注入如高对比度分辨力、图像均匀性、典型值/最大值 KAP 相关等项的 `{前缀}_判定标准`（格式多为 `≥{v}`、`≤{v}`）。低对比度分辨力根据是否存在 `lowContrastResolutionMaxMm` 在 `≥` 与 `≤` 间切换。 |
| `_inject_default_report_row_verdict_criteria` | 无套表判定标准列时，为透视典型值/最大值（普通、高剂量）等行写入院内常用数字限值（如 `<=25.0`、`<=88.0`、`<=176.0`）。 |
| `_inject_shield_zone_operator_row_criteria` | 「透视防护区…术者位×高度」类行：补缺 `…_判定标准`；优先复用映射内已有同文标准；否则用 constants 中 `shieldZoneAmbientDoseEqRateLimit` / `shieldZoneDoseRateLimit`；再无则用内置默认（如 `≤400` μSv/h 量级，见代码常量）。 |

以上均为**补缺**，不覆盖已有 `value_mapping` 中非空判定标准。

---

## 7. 与模板、步骤（steps）的协作

- **`_attach_step_schema_to_pdf_fields`**：把 unified 模板 steps 里控件上的 `source` 以及 `judgmentCriterionText` 等挂到 PDF 坐标字段上，便于 `_get_judgment_criterion_text` 从字段上直接读到标准。  
- **矩阵表**：单项判定单元格的 `pdfFieldId` 用于在 matrix 中定位行，再按序号锚点取同行「判定标准」列（见第 3 节）。

---

## 8. 小结表

| 问题 | 结论 |
|------|------|
| 单项判定谁算？ | 优先由 `verdict_from_measurement` 根据**判定标准句 + 检测结果数值**计算；算不出再用提交数据中的合格/不合格。 |
| 何时不算？ | 无标准、无数值、测量串像标准句、或引擎返回 `None`。 |
| 为何分两遍？ | 先保证检测结果等已写入模板字段和映射，再算单项判定，避免顺序依赖错误。 |
| 数值规则在哪改？ | 比较符与区间语法主要在 `utils/verdict_from_criterion.py`；业务上「谁和哪条标准配对」在 `inspection_report_make.py`。 |

---

## 9. 维护建议

- 新增标准句式：优先扩展 `verdict_from_criterion._eval_simple` 及 `_match_*`，并补充单元测试（若项目后续允许测试）。  
- 新增表格行类型：检查 `_verdict_measurement_placeholder_key_candidates` 与 `_inject_*` 是否需新前缀或 constants 键。  
- 与 PDF 红框命名不一致时：先对齐 `HTMLPDF_AUTO_RED_BOX_RULES.md` 中的 `{前缀}_单项判定` 命名，再核对 `value_mapping` 键是否一致。
