# 打包与新设备安装说明（全量迁移）

> **用途**：把现有 Django 项目（`tablet_backend`）**整机搬迁**到新设备：代码 + **数据库** + **全部 media** + **运行配置** + **Python/Node 依赖环境**（及可选 OCR/TeX）。  
> **整理日期**：2026-08-20（修订：以全量迁移为主路径）  
> **关联**：[部署流程-从零安装与源码保护评估.md](部署流程-从零安装与源码保护评估.md)、[01-configuration.md](01-configuration.md)、[06-scripts-and-admin.md](06-scripts-and-admin.md)

默认端口：**11223**（`DJANGO_PORT` 可覆盖）。  
下文源机项目根目录（含 `manage.py`）记为 **`$SRC`**，新机安装目录记为 **`$APP`**（示例 `/opt/tablet_backend`）。

---

## 0. 迁移目标（你要搬走的「全部」）

| 类别 | 必须带走 | 说明 |
|------|----------|------|
| 应用代码 | `apps/`、`tablet_backend/`、`templates/`、`static/`、`htmlpdf/`、`utils/`、`converter/`、`latex/`、`f1_eval_report/`、`radiation_detection_report/`、`manage.py`、`docs/` 等 | 主站运行所需源码与资源 |
| 字体 | `fonts/`（含 `SIMSUN.TTC` 等） | PDF 中文；体积约数百 MB，**勿漏** |
| 数据库 | `db.sqlite3`（及停服时的 `-wal`/`-shm` 若存在） | 用户、项目、文件库元数据等 |
| 业务文件 | **整个 `media/`** | 文件库、模板、报告、F.1、评价报告书工作区、签名、OTA APK…（可达十余 GB） |
| 运行时配置 | 根目录 `*_runtime.json` | 见下表 |
| Python 依赖 | `requirements.txt` + **源机 `pip freeze`** +（推荐）离线 wheel 包 | 新机重建 `.venv`，**不要**直接拷异构 `.venv` |
| Node 依赖 | `package.json`、`package-lock.json` +（推荐）离线 `node_modules` 或新机 `npm ci` | 公式叠印 / 流程练习 |
| 系统级 | 系统包清单、Ollama 模型、TeX（若在用） | 与旧机能力对齐 |

**根目录运行时 JSON（有则一并拷贝）：**

| 文件 | 用途 |
|------|------|
| `app_ota_runtime.json` | App OTA 版本与 APK 元数据 |
| `jwt_runtime.json` | JWT 寿命等 |
| `pdf_fill_runtime.json` | PDF 填报相关 |
| `decimal_precision_runtime.json` | 小数精度 |
| `llm_runtime.json` | LLM/管线提示相关 |

**建议仍排除（不属于业务「全部」，且易出问题）：**

| 排除 | 原因 |
|------|------|
| `.venv/` / `venv/` | 绝对路径与 CPU/CUDA 绑定；用 freeze + 重装还原环境 |
| `__pycache__/`、`*.pyc` | 无用 |
| `.git/` | 可选；交付甲方时常去掉 |
| `.cursor/`、内部 agent 记录、`output.log` | 非业务 |
| `staticfiles/` | 新机 `collectstatic` 再生即可 |

`backups/`、`logs/`：需要历史备份则拷贝；否则可排除以省空间。

> **原则**：业务数据（库 + media + runtime）原样带走；**依赖环境用清单/离线包在新机等价重建**，这样最稳。仅当源机与新机 **OS、架构、Python 小版本完全一致** 时，才可尝试整目录拷贝 `.venv` / `node_modules`（见 §1.5）。

## 1. 源机器：停服 → 导出环境 → 打包/同步

### 1.1 停服（避免库与 media 不一致）

```bash
cd "$SRC"
# 按实际停掉：Ctrl+C 结束 runserver，或：
# sudo systemctl stop tablet-backend
# 确认无进程再占用 db / media
```

可选：先打一份库备份再打包。

```bash
source .venv/bin/activate   # 若已有虚拟环境
python manage.py backup_database   # 若命令可用；或手动 cp
cp -a db.sqlite3 "db.sqlite3.pre-migrate.$(date +%Y%m%d%H%M).bak"
```

### 1.2 导出「环境和依赖」清单（必做）

在源机**当前正在用的**虚拟环境中：

```bash
cd "$SRC"
source .venv/bin/activate

python -V > migrate_python_version.txt
pip freeze > requirements-freeze.txt
pip list --format=columns > migrate_pip_list.txt

# Node
node -v > migrate_node_version.txt 2>/dev/null || true
npm -v >> migrate_node_version.txt 2>/dev/null || true
cp -a package.json package-lock.json ./   # 已在根目录则跳过

# 系统包（Ubuntu/Debian，便于新机对齐）
dpkg --get-selections > migrate_dpkg_selections.txt 2>/dev/null || true
# 至少记录这些是否已装：python3、poppler-utils、libgl1、nodejs、texlive 等

# Ollama（若在用）
ollama list > migrate_ollama_list.txt 2>/dev/null || true
echo "OLLAMA_HOST=${OLLAMA_HOST:-http://127.0.0.1:11434}" >> migrate_env_hints.txt
echo "EQUIPMENT_MODEL_NAME=${EQUIPMENT_MODEL_NAME:-qwen3:14b-q4_K_M}" >> migrate_env_hints.txt
echo "MINERU_BACKEND=${MINERU_BACKEND:-pipeline}" >> migrate_env_hints.txt
echo "SECRET_KEY 请在新机单独设置，勿把生产密钥明文写进文档仓库" >> migrate_env_hints.txt

# 目录体积自检（心里有数）
du -sh media db.sqlite3 fonts .venv node_modules 2>/dev/null | tee migrate_du.txt
```

将上述 `migrate_*.txt`、`requirements-freeze.txt` **放入交付目录**，与数据包一起带走。

### 1.3 制作 Python 离线依赖包（推荐，保证环境可还原）

在与新机尽量相同的平台上执行（同架构：如都是 `x86_64` Linux；Python 建议 **3.12**，与 `requirements.txt` 一致）：

```bash
cd "$SRC"
source .venv/bin/activate
mkdir -p offline-wheels
pip download -r requirements-freeze.txt -d offline-wheels
# 若 freeze 过大/含本地路径包，可退化为：
# pip download -r requirements.txt -d offline-wheels
pip download gunicorn -d offline-wheels   # 生产常驻用
tar -czf tablet_backend-wheels-$(date +%Y%m%d).tar.gz offline-wheels requirements-freeze.txt requirements.txt
```

> MinerU / torch 与 CUDA 强相关。若源机有 GPU、新机无 GPU（或反之），离线 wheel 可能装不上——此时在新机改为在线安装，或按「无 OCR」降级（Django 主站仍可用）。

### 1.4 打包业务与代码（推荐拆成 3 包）

`media` 往往很大（示例环境可达 **15GB+**），**强烈建议与代码、数据库分开**，或改用 `rsync`（§1.6）。

```bash
cd "$SRC"
VER=$(date +%Y%m%d)
APP_NAME=tablet_backend

# ---------- 包 1：代码 + 字体 + 配置 + 依赖清单（不含 media/db/.venv）----------
tar -czf "${APP_NAME}-${VER}-app.tar.gz" \
  --exclude='.venv' \
  --exclude='venv' \
  --exclude='.git' \
  --exclude='node_modules' \
  --exclude='__pycache__' \
  --exclude='*.pyc' \
  --exclude='media' \
  --exclude='db.sqlite3' \
  --exclude='db.sqlite3-journal' \
  --exclude='db.sqlite3-wal' \
  --exclude='db.sqlite3-shm' \
  --exclude='staticfiles' \
  --exclude='.cursor' \
  --exclude='output.log' \
  \
  manage.py requirements.txt requirements-freeze.txt \
  package.json package-lock.json \
  migrate_*.txt \
  README.md docs openapi.yaml \
  tablet_backend apps templates static htmlpdf utils \
  converter latex fonts f1_eval_report radiation_detection_report \
  scripts \
  app_ota_runtime.json jwt_runtime.json pdf_fill_runtime.json \
  decimal_precision_runtime.json llm_runtime.json \
  2>/dev/null

# 若某些 runtime json 不存在，上面可能告警，可改为显式列存在的文件，例如：
# tar -czf ... $(ls app_ota_runtime.json jwt_runtime.json ... 2>/dev/null) ...

# ---------- 包 2：数据库 ----------
tar -czf "${APP_NAME}-${VER}-db.tar.gz" \
  db.sqlite3 \
  db.sqlite3-wal db.sqlite3-shm 2>/dev/null || \
tar -czf "${APP_NAME}-${VER}-db.tar.gz" db.sqlite3

# ---------- 包 3：全部 media ----------
tar -czf "${APP_NAME}-${VER}-media.tar.gz" media

# ---------- 包 4：Python 离线 wheel（若已做 §1.3）----------
# 已有 tablet_backend-wheels-*.tar.gz 即可
```

**可选：把 Node 依赖一并带走（同 OS/架构时）：**

```bash
tar -czf "${APP_NAME}-${VER}-node_modules.tar.gz" node_modules
```

新机若架构不同，不要用此包，改在新机执行 `npm ci`。

### 1.5 仅当「源机 ≈ 新机」时：整目录拷虚拟环境

同时满足才可考虑拷 `.venv`：

- 同一发行版大类（如都是 Ubuntu 22.04/24.04）  
- 同一 CPU 架构（`uname -m`）  
- 同一 Python 小版本（如都是 3.12.x）  
- 无「源机有 CUDA、新机无」这类差异  

```bash
# 不推荐作为默认方案；失败率高于 pip 重装
tar -czf "${APP_NAME}-${VER}-venv.tar.gz" .venv
```

新机解压后若 `python` 报错或动态库缺失，删除 `.venv` 改走 §3.2 重装。

### 1.6 大盘推荐：rsync 直推（可断点续传）

新机已建好空目录且能 SSH 时：

```bash
# 在源机执行；NEWHOST / 用户按实际改
NEW=tablet@NEWHOST
REMOTE_APP=/opt/tablet_backend

# 先推应用（排除 venv/media/db，db 与 media 单独推）
rsync -aH --info=progress2 \
  --exclude '.venv/' --exclude 'venv/' --exclude '.git/' \
  --exclude 'node_modules/' --exclude '__pycache__/' \
  --exclude 'media/' --exclude 'db.sqlite3*' \
  --exclude 'staticfiles/' --exclude '.cursor/' \
  "$SRC"/ "$NEW:$REMOTE_APP/"

# 再推库与全部 media（停服后）
rsync -aH --info=progress2 "$SRC"/db.sqlite3 "$NEW:$REMOTE_APP/"
rsync -aH --info=progress2 "$SRC"/media/ "$NEW:$REMOTE_APP/media/"

# 依赖离线包
rsync -aH offline-wheels/ "$NEW:$REMOTE_APP/offline-wheels/"
# 或 rsync wheels 的 tar.gz
```

### 1.7 全量交付装箱单

| 序号 | 物品 | 备注 |
|------|------|------|
| 1 | `*-app.tar.gz` | 代码 + fonts + runtime + migrate 清单 |
| 2 | `*-db.tar.gz` | `db.sqlite3` |
| 3 | `*-media.tar.gz` 或 rsync 完成证明 | **全部** `media/` |
| 4 | `*-wheels.tar.gz` 或 `offline-wheels/` | Python 环境还原 |
| 5 | `*-node_modules.tar.gz` 或新机联网 `npm ci` | Node 环境 |
| 6 | `requirements-freeze.txt` + `migrate_*.txt` | 验收对照 |
| 7 | Ollama 模型目录（若 OCR 也要原样） | 常见 `~/.ollama`；体积大 |
| 8 | 账号与 `SECRET_KEY` 交接（线下，勿进 Git） | 登录与会话 |

## 2. 新设备：系统准备

### 2.1 磁盘

`media` + 字体 + wheel + 余量。例如源机 `media` 约 15G、`fonts` 约 350M，建议预留 **≥ 2× media + 20G**。

### 2.2 系统包（与源机对齐）

```bash
sudo apt update
sudo apt install -y \
  build-essential curl wget \
  python3 python3-venv python3-dev \
  poppler-utils \
  libgl1 libglib2.0-0 \
  fonts-dejavu-core
```

对照源机 `migrate_dpkg_selections.txt` / `migrate_python_version.txt`：

- 安装 **同主版本** Python（优先 3.12；若 freeze 来自 3.10，新机也应 3.10，避免二进制不兼容）。  
- Node.js **18+/20 LTS**（与 `migrate_node_version.txt` 接近）。  
- 若源机有评价报告书编译：安装 TeX Live（`lualatex`/`xelatex`）。  
- 若源机有 OCR：安装 Ollama，并导入模型（或 `ollama pull`）。

```bash
sudo useradd -r -m -s /bin/bash tablet || true
sudo mkdir -p /opt/tablet_backend /var/log/tablet
sudo chown -R tablet:tablet /opt/tablet_backend /var/log/tablet
export APP=/opt/tablet_backend
```

## 3. 新设备：还原「全部文件 + 环境」

### 3.1 解压 / 就位

```bash
sudo -u tablet -H bash
export APP=/opt/tablet_backend
cd "$APP"

# 若用 tar：
tar -xzf /path/to/tablet_backend-*-app.tar.gz -C "$APP"
# 视 tar 结构可能需要把内容挪到 $APP 根，确保：
test -f "$APP/manage.py"

tar -xzf /path/to/tablet_backend-*-db.tar.gz -C "$APP"
tar -xzf /path/to/tablet_backend-*-media.tar.gz -C "$APP"

# 确认三件套都在
ls -lh "$APP/manage.py" "$APP/db.sqlite3"
du -sh "$APP/media" "$APP/fonts"
ls "$APP"/*_runtime.json 2>/dev/null
```

权限：

```bash
chown -R tablet:tablet "$APP"
chmod -R u+rwX "$APP/media" "$APP/db.sqlite3"
```

### 3.2 还原 Python 环境（依赖）

**推荐：离线 wheel + freeze（与源机包版本一致）**

```bash
cd "$APP"
python3 -m venv .venv
source .venv/bin/activate
pip install -U pip wheel

# 若已解压 offline-wheels：
tar -xzf /path/to/tablet_backend-*-wheels.tar.gz -C "$APP"   # 若尚未解压
pip install --no-index --find-links="$APP/offline-wheels" -r requirements-freeze.txt
# freeze 失败时退一步：
# pip install --no-index --find-links="$APP/offline-wheels" -r requirements.txt
pip install --no-index --find-links="$APP/offline-wheels" gunicorn

python -c "import django; print(django.get_version())"
```

**有外网时：**

```bash
pip install -r requirements-freeze.txt || pip install -r requirements.txt
pip install gunicorn
```

**若拷贝了 `.venv` 包：** 解压后 `source .venv/bin/activate`，跑 `python manage.py check`；异常则删掉重建。

### 3.3 还原 Node 环境

```bash
cd "$APP"
# 方案 A：同架构已打包 node_modules
tar -xzf /path/to/tablet_backend-*-node_modules.tar.gz -C "$APP"

# 方案 B：联网重装（更稳）
npm ci    # 有 package-lock.json 时
# 或：npm install
```

### 3.4 环境变量

至少：

```bash
export SECRET_KEY='与源机一致或新生成（改了会导致旧 Session/部分签名行为变化，按安全策略选）'
export DJANGO_PORT=11223
export OLLAMA_HOST=http://127.0.0.1:11434
export EQUIPMENT_MODEL_NAME=qwen3:14b-q4_K_M   # 与 migrate_ollama_list / 源机一致
export MINERU_BACKEND=pipeline
```

写入 systemd 或启动脚本持久化。  
说明：当前 `settings.py` 中 `DEBUG` 默认写死 `True`；生产请改配置或发布分支后再上线。

### 3.5 数据库与 media 校验（全量迁移后）

**不要**对已有业务库执行会覆盖数据的种子（如盲目 `init_data`），除非明确需要补菜单。

```bash
cd "$APP"
source .venv/bin/activate

python manage.py migrate                 # 只补迁移，不丢数据
python manage.py check_library_media --dry-run
# 若 dry-run 显示大量缺失，说明 media 未拷全或路径不对——先补 media，勿直接改库

python manage.py collectstatic --noinput
```

### 3.6 还原 Ollama / TeX（若源机在用）

- **Ollama**：安装服务后，拷贝源机 `~/.ollama`（或服务用户下的模型目录），或按 `migrate_ollama_list.txt` 重新 `pull`。  
- **TeX**：安装与源机接近的 TeX Live，确认 `which lualatex` / `xelatex`。

### 3.7 启动与验收

```bash
python manage.py runserver 0.0.0.0:11223
# 或 gunicorn tablet_backend.wsgi:application --bind 0.0.0.0:11223 --workers 2 --timeout 300
```

| 检查项 | 期望 |
|--------|------|
| 用**旧机同一账号**登录 | 成功（说明 db 已迁） |
| 文件库打开**已知 PDF** | 能预览（说明 media 已迁） |
| 历史检测报告 / 现场记录 | 可下载 |
| F.1 / 评价报告书列表 | 与旧机一致（工作区在 media 内） |
| OTA / 签名 | `media/apk`、`media/user_signatures` 正常 |
| `pip freeze` 与源机 freeze 关键要包版本 | 大致一致 |
| OCR（若需要） | `curl $OLLAMA_HOST/api/tags` 含原模型 |

更全验收见部署文档 §5。常驻 systemd/Nginx 见该文档 §4.9。

## 4. 全量迁移推荐时间线（一张清单）

```text
源机                          新机
─────────────────────────────────────────────────────
1. 停服
2. 导出 freeze / migrate_*.txt
3. 制作 offline-wheels
4. 打包 app + db + media
   （或 rsync 直推）         ←── 传输 ──→  5. 装系统包 / Python / Node
                                          6. 解压 app+db+media
                                          7. venv + pip（离线/在线）
                                          8. npm ci（或解压 node_modules）
                                          9. 环境变量 + Ollama/TeX
                                         10. migrate + check_library_media
                                         11. 启动验收
12. 切流量后旧机只读保留数日
```

## 6. 常见问题

| 现象 | 处理 |
|------|------|
| 能登录但文件全是坏的/404 | `media/` 未拷全或权限不对；对比源机 `du -sh media` |
| 登录失败 / 用户不存在 | 用了空库或拷错 `db.sqlite3`；确认停服后拷的那份 |
| SQLite「database is locked」 | 停净旧进程；不要两边同时写同一份通过网络盘挂载的库 |
| `pip install` 与 freeze 冲突 | 用同版本 Python；GPU/CPU 包不匹配时去掉 CUDA 相关包再装 |
| PDF 中文方框 | 确认 `$APP/fonts/SIMSUN.TTC` 存在 |
| 启动极慢 | 大 media 完整性扫描：临时 `LIBRARY_MEDIA_INTEGRITY_ON_STARTUP=0` |
| 评价报告书不能编译 | 新机未装 TeX；与源机 `LATEX_ENGINE` 一致 |
| 直接拷了 `.venv` 无法运行 | 删 `.venv`，按 §3.2 用 wheels/freeze 重建 |
