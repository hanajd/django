# 质控拍照照片提交 JSON 说明

本文给后端说明当前 Flutter 端“质控拍照/查看图片”里的照片是怎么随检测任务提交到后端的。

## 1. 接口

质控表单最终提交走检测任务提交接口：

```http
POST /api/v2/inspections/projects/{projectId}/tasks/{taskNo}/submit
Content-Type: application/json
```

注意：质控留存照片不是 multipart 文件上传，而是放在提交 JSON 的根字段 `sectionPhotos` 里。

## 2. 前端塞入 JSON 的流程

1. 用户在某个质控 section 点击拍照或从相册选择图片。
2. 前端把原图压缩到最大宽度 1920，并生成带时间/地点水印的 JPEG。
3. 前端把水印后的 JPEG 字节转成 Data URL：

```text
data:image/jpeg;base64,{JPEG_BASE64}
```

4. 前端把照片记录追加到动态表单 values 的 `sectionPhotos` 数组。
5. 提交时，`sectionPhotos` 原样放到最终提交 JSON 的根级字段。

对应代码位置：

- `lib/services/photo_capture_service.dart`：生成水印 JPEG 和 `dataUrl`
- `lib/features/dynamic_form/widgets/form_step_content.dart`：追加 `sectionPhotos`
- `lib/features/inspection/services/inspection_api_service.dart`：构建 `/submit` 请求体

## 3. 最终提交 JSON 结构

`sectionPhotos` 是可选字段；用户没有拍照时不会带这个字段。

```json

  "reportType": "ct_qc",
  "createdAt": "2026-05-18T10:00:00.000",
  "updatedAt": "2026-05-18T10:30:00.000",
  "dynamicData": {},
  "reportInfo": {},
  "hospitalInfo": {},
  "equipmentInfo": {},
  "instruments": [],
  "sectionPhotos": [
    {
      "path": "/data/user/0/app/documents/section_photos/1779071400000.jpg",
      "dataUrl": "data:image/jpeg;base64,/9j/4AAQSkZJRgABAQAAAQABAAD...",

```

## 4. `sectionPhotos[]` 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `path` | string | 前端本地保存路径，只用于客户端预览/排查；后端不要当成可访问 URL。 |
| `dataUrl` | string | 照片正文。格式为 `data:image/jpeg;base64,{base64}`，后端从这里解码出 JPEG 文件。 |
| `capturedAt` | string | 拍照时间，Dart `DateTime.toIso8601String()` 生成。 |
| `location` | string | 水印上的地点文本，通常由 section 的地点提示和设备位置拼出来。 |
| `source` | string | 图片来源：`camera` 表示拍照，`gallery` 表示相册选择。 |
| `sectionId` | string | 当前质控分组 ID。 |
| `sectionTitle` | string | 当前质控分组标题。 |
| `sectionSourceIds` | string[] | 合并/展示后的原始 section ID 列表，用于后端按模板 section 归档。 |
| `kind` | string | 照片用途：`inspection` 表示普通留存照片，`ocr` 表示设备信息 AI 识别时拍的铭牌照片。 |

## 5. 后端接收建议

后端接收 `/submit` 的 JSON 后，按下面逻辑处理：

1. 从根字段读取 `sectionPhotos`，不存在或为空时跳过。
2. 遍历数组，读取每条的 `dataUrl`。
3. 去掉 `data:image/jpeg;base64,` 前缀，只保留 base64 正文。
4. Base64 解码为 JPEG 字节。
5. 保存文件，例如：

```text
inspection-photos/{projectId}/{taskNo}/{sectionId}/{capturedAt}.jpg
```

6. 数据库保存照片元数据：`taskNo`、`projectId`、`sectionId`、`sectionTitle`、`kind`、`source`、`capturedAt`、`location`、`filePath`。

伪代码：

```pseudo
photos = requestJson.sectionPhotos ?: []

for photo in photos:
    dataUrl = photo.dataUrl
    base64Text = substringAfter(dataUrl, "base64,")
    bytes = base64Decode(base64Text)

    filePath = saveJpeg(projectId, taskNo, photo.sectionId, photo.capturedAt, bytes)

    insert inspection_section_photo {
        project_id: projectId,
        task_no: taskNo,
        section_id: photo.sectionId,
        section_title: photo.sectionTitle,
        kind: photo.kind,
        source: photo.source,
        captured_at: photo.capturedAt,
        location: photo.location,
        file_path: filePath
    }
```

## 6. 大小限制

因为照片是 base64 放进 JSON，体积大约会比 JPEG 原文件增加 33%。后端和网关需要放开 JSON 请求体大小限制，否则多张照片提交时可能被拒绝。

建议至少按以下方向配置：

- Nginx/反向代理：调大 `client_max_body_size`
- Node/Express：调大 `express.json({ limit: "50mb" })`
- Java/Spring：确认网关、Servlet 容器、JSON body 读取限制足够

## 7. 和 OCR 上传接口的区别

设备信息 AI 识别会额外调用 OCR 上传接口：

```http
POST /api/v2/inspections/projects/{projectId}/tasks/{taskNo}/ocr/upload
Content-Type: multipart/form-data
Form field: file
```

这个接口只用于“立即识别设备铭牌”。最终提交任务时，识别用的照片如果已加入表单，仍会作为 `sectionPhotos[]` 里的 `kind: "ocr"` 记录随 `/submit` JSON 一起提交。
