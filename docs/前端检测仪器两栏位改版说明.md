# 前端检测仪器改版说明（初版 `instruments[]` → 质控 / 防护两个主仪器）

面向 App / Flutter / Web 表单：如何把「一台或多台仪器列表」改为 **两个独立的主要检测仪器输入框**，并与新版 `export-frontend-json` 对齐。

---

## 1. 改了什么（一句话）

| 维度 | 初版 | 现版 |
|------|------|------|
| 界面 | 根级 `instruments[]` 多行列表 / 多槽位 `instrument1`… | **两个** `instrument_select`：质控一台、防护一台 |
| 所在章节 | 常在「仪器及人员」或混在多处 | **固定**在 `sectionType: "instrumentPersonnel"`（受检设备主要检测仪器及检测人员） |
| 语义 | 按下标 `instruments[0]`、`instruments[1]` | 按作用域 `instruments.qualityControl`、`instruments.radiationProtection` |
| 后台绑定 | 任务模板勾选多台、按顺序对应槽位 | 后台 **分开** 绑定质控仪器、防护仪器（互不依赖顺序） |

第四、五章（质控检测结果 / 防护检测结果）**不再**放置仪器选择控件；`instrumentScope` 只表示「这台仪器用于哪类检测」，**不是**章节类型。

---

## 2. 从哪里读配置

### 2.1 拉模板

```
GET /api/v2/inspections/projects/{projectId}/tasks/{taskNo}/export-frontend-json
```

默认 `mode=runtime`，响应为紧凑 JSON（无 `pdf` 坐标）。

### 2.2 定位章节（不要用中文 title 硬编码）

```text
steps[].sections[] 中 sectionType === "instrumentPersonnel"
```

典型字段：

| 字段 | 值 |
|------|-----|
| `sectionType` | `instrumentPersonnel` |
| `sectionKey` | `instrument_personnel` |
| `id` | `sec_instrument_personnel` |
| `title` | 受检设备主要检测仪器及检测人员 |
| `capabilities` | 含 `"instrumentSelect"`（提示本章有仪器下拉） |

### 2.3 定位两个输入框

在 **`instrumentPersonnel` 章节的 `fields[]`** 中筛选：

```text
type === "instrument_select"
```

每个栏位至少包含：

| 字段 | 说明 |
|------|------|
| `id` | 与 `pdfFieldId` 一致，如 `f12` |
| `pdfFieldId` | PDF 回填键，**必填写入 `dynamicData`** |
| `label` | 展示名，可重名；示例见下 |
| `instrumentScope` | `qualityControl` 或 `radiationProtection` |
| `registrySlot` | `1`（质控）或 `2`（防护） |
| `submitPath` | `instruments.qualityControl` / `instruments.radiationProtection` |
| `submitBucket` | `instruments` |

标签示例（以模板为准，勿写死）：

- `主要检测仪器_质量控制（性能）检测`
- `主要检测仪器_工作场所放射防护检测`

**匹配优先级建议：** `instrumentScope` → `submitPath` → `registrySlot`（1/2）→ `label` 关键字。

### 2.4 根级默认值（任务模板预绑）

```json
{
  "instruments": [
    { "id": "12", "instrumentId": "12", "identifier": "…", "name": "…", "model": "…", "certificateNo": "…", "validUntil": "…", "enabled": true }
  ],
  "instrumentBindings": [
    {
      "scope": "qualityControl",
      "sectionType": "instrumentPersonnel",
      "submitPath": "instruments.qualityControl",
      "registrySlot": 1,
      "defaultInstrumentId": "12"
    },
    {
      "scope": "radiationProtection",
      "sectionType": "instrumentPersonnel",
      "submitPath": "instruments.radiationProtection",
      "registrySlot": 2,
      "defaultInstrumentId": "15"
    }
  ]
}
```

- **`instrumentBindings`**：后台为质控、防护 **分别** 选的默认仪器 id（字符串）。
- **`instruments[]`**：仍为数组，便于兼容旧逻辑；导出时多为「质控条目 + 防护条目」（去重后最多 2 条）。**无用户提交时**用模板绑定预填。

## 3. 仪器台账（下拉数据源）

全量列表 **不在** 导出 JSON 里，请调登记接口，例如：

```
GET /api/v2/registry/instruments/
```

（以你们环境实际路径为准。）

下拉项展示建议与报告/PDF 一致：

```text
{model} {name} {identifier}（有效期至yyyy年mm月dd日）
```

无有效期则省略括号段；单行 `nowrap` + 必要时 `ellipsis`。

## 4. 表单状态与提交（重点）

### 4.1 本地表单模型（推荐）

用 **`submitPath`** 作逻辑键，不要再用「仪器列表下标」区分质控/防护：

```dart
// 示例结构
form.instruments.qualityControl   // 仪器主键 id 或完整条目对象
form.instruments.radiationProtection
```

与模板栏位双向绑定：

| 栏位 | 读写路径 |
|------|----------|
| 质控 `instrument_select` | `instruments.qualityControl` |
| 防护 `instrument_select` | `instruments.radiationProtection` |

### 4.2 `dynamicData`（PDF 回填必写）

服务端写 PDF 时，对 `instrument_select` **优先** 用：

```text
dynamicData[pdfFieldId] = 仪器主键 id（字符串）
```

或完整对象（与旧版一致）。**每个** `instrument_select` 各写一格，例如：

```json
"dynamicData": {
  "f12": "12",
  "f34": "15"
}
```

`pdfFieldId` 来自栏位定义，**不要**用 `label` 当键。

### 4.3 提交体 `instruments`（与现有校验兼容）

当前提交/草稿接口序列化器仍校验 **`instruments` 为数组**（`ListField`）。过渡期请 **同时** 维护：

1. **嵌套语义（表单内、写入 `raw_payload`）**  
   - `instruments.qualityControl` / `instruments.radiationProtection`  
   - 可为 id 字符串或 §2.4 同款对象。

2. **数组形态（通过校验、写入关系表）**  
   - `instruments[0]` → 质控仪器完整条目（`registrySlot === 1`）  
   - `instruments[1]` → 防护仪器完整条目（`registrySlot === 2`）  
   - 仅绑了一台时，数组可能只有 1 条；不要假设 `[0]` 一定是质控，应以 `instrumentScope` 为准组数组。

3. **`dynamicData`**（见 §4.2）

**推荐组装顺序（提交前）：**

```text
1. 用户选择质控仪器 → 写入 instruments.qualityControl + dynamicData[质控栏位.pdfFieldId]
2. 用户选择防护仪器 → 写入 instruments.radiationProtection + dynamicData[防护栏位.pdfFieldId]
3. 由 scope 生成 instruments[] = [质控条目?, 防护条目?]（去重，质控在前）
4. 整包 POST 草稿/提交
```

条目字段与初版相同：`id` / `instrumentId` / `identifier` / `name` / `model` / `certificateNo` / `validUntil` / `enabled`。

### 4.4 初版逻辑请停用

| 初版 | 现版 |
|------|------|
| 在 `qualityControl` / `radiationProtection` 章节找仪器控件 | 只在 `instrumentPersonnel` |
| `instruments[0]`=质控、`instruments[1]`=防护 的硬编码 | 以 `instrumentScope` / `submitPath` 为准 |
| 根级 `instruments[]` 多行增删 UI | 两个固定 `instrument_select`（除非模板另有 `table` 仪器清单） |
| 依赖 `instrumentCatalogOptions` 嵌在导出 JSON | 改调 registry API |
| 按勾选顺序理解后台绑定 | 后台为质控、防护 **独立** 各绑一台 |

## 5. 渲染伪代码（Flutter 思路）

```dart
final personnelSec = steps
  .expand((s) => s.sections)
  .firstWhere((sec) => sec.sectionType == 'instrumentPersonnel');

final instrumentFields = personnelSec.fields
  .where((f) => f.type == 'instrument_select')
  .toList();

InstrumentSelectField? qcField;
InstrumentSelectField? rpField;
for (final f in instrumentFields) {
  if (f.instrumentScope == 'qualityControl' ||
      f.submitPath == 'instruments.qualityControl' ||
      f.registrySlot == 1) {
    qcField = f;
  } else if (f.instrumentScope == 'radiationProtection' ||
      f.submitPath == 'instruments.radiationProtection' ||
      f.registrySlot == 2) {
    rpField = f;
  }
}

// 初值：instrumentBindings.defaultInstrumentId 或 instruments[] 中按 scope 匹配
// 变更：更新嵌套路径 + dynamicData[pdfFieldId] + 重建 instruments[]
```

同章可能还有：人员签字、日期、`instrumentSlot` 分组（旧多槽位勾选+文本+日期）。**仅** `type === instrument_select` 走本说明；其余仍按原 `FieldDef` 渲染。

---

## 6. 草稿 / 回显

1. 读 `GET` 草稿或已提交任务的 `raw_payload`。  
2. 优先从 `instruments.qualityControl` / `instruments.radiationProtection` 还原（若为对象）。  
3. 否则从 `instruments[]` + 模板 `instrumentBindings` / 栏位 `registrySlot` 推断。  
4. 再与 `dynamicData[pdfFieldId]` 交叉校验。  
5. 缺字段仅有 id 时，用 registry API 补全展示（与初版一致）。

---

## 7. 自测清单

- [ ] 仅在 **instrumentPersonnel** 章渲染 2 个仪器下拉（或模板实际数量）。  
- [ ] 质控、防护可选 **不同** 仪器；互不影响。  
- [ ] 提交后 `dynamicData` 含两个 `pdfFieldId`。  
- [ ] 提交后 `instruments[]` 含 1～2 条完整条目，且与 scope 一致。  
- [ ] 第四、五章 **无** `instrument_select`。  
- [ ] 换任务模板后，初值来自 `instrumentBindings`，而非写死 `[0]`/`[1]`。  
- [ ] PDF/报告仪器展示正常（后端按 id 解析主数据）。
