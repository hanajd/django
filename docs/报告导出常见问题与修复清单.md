# 报告 PDF 导出常见问题与修复清单

本文档汇总「现场记录 → 报告」自动导出链路中已发现的问题、根因与代码修复位置，供后续各设备类型报告回归时对照。

## 流程要点

1. 勾选现场记录 PDF → `accumulate_inspection_payloads_ordered_merge` 合并多份提交 JSON  
2. `_fill_template_fields_with_submit` 构建 `value_mapping` 并 HTMLPDF 回填  
3. `apply_report_site_field_map_to_value_mapping` 显式映射（`report_site_field_configs`）  
4. `try_enrich_report_pdf_with_radiation_table` 嵌入第五章防护表  
5. `finalize_single_report_pdf`：封面/基本情况叠印、目录、页眉页码  

**环境**：本地导出可用 `conda run -n MinerU python manage.py shell` 调用 `scripts/export_dsa_report_260001.py`，不占用正在运行的 `runserver`。

## 一、封面与基本情况（叠印 vs 映射回填）

| 现象 | 根因 | 修复 |
|------|------|------|
| 「放射防 护」「防 护检测」多空格 | PDF 折行/模板预印字拆开词组 | `utils/pdf_merge._normalize_rp_phrase_spacing`；叠印前对 `cover_title`/`org` 归一化 |
| 封面「受检单位」用小四映射字而非四号叠印 | 报告 f4 被 HTMLPDF 回填占用 | `ReportTemplateProfile.cover_overlay_pdf_field_ids`（DSA: f2–f5）；`_is_report_cover_overlay_pdf_field` 跳过回填 |
| 封面「项目名称」压线、宽度不足、第二行偏下 | 未启用「标签下划线之间写入」策略 | DSA 使用 `DSA_STATUS_REPORT_PROFILE`：`cover_project_name_write_below_label=True` 等 |
| 基本情况「项目名称/评价/台数」与封面不一致 | 应由叠印写入，却被映射填满 | `_REPORT_SUMMARY_OVERLAY_MANAGED_KEYS` + `_strip_report_summary_overlay_keys_from_mapping` |
| 评价正文整体偏右 | `evaluation_write_x0` 默认 176pt | DSA/CT 等 Profile 设为约 78.5pt（左移约八个汉字） |
| 受检设备台数「2台台」、压左线 | 叠印带「台」+ 模板格旁另有「台」 | `device_count_include_unit_suffix=False`（DSA） |
| 联系人错、电话对 | `commissionContactPhone` 被现场 f7 污染；DSA f9/f10 与默认 f4/f5 语义不同 | `_resolve_commission_contact_from_submit` 优先 f4 整格；`_DSA_REPORT_BASIC_INFO_SLOT_SEMANTICS` |
| 委托单位名称错 | reconcile 将 f7 当作委托单位（DSA 上 f7=受检单位名称） | Profile 槽位语义 + f12←f521/委托单位名称 |
| 受检单位地址未红字回填 | f8 未按语义写入 | `htmlpdf_basic_info_pdf_field_ids` + reconcile 写 f8 |

**配置入口**：`apps/core/report_template_profiles.py`（`dsa-2` / `dsa` / `dsa-1` / `ctc-1` / `cbct-linac-status-report`）。

## 二、页眉页码

| 现象 | 根因 | 修复 |
|------|------|------|
| 「第 n 页/共 m 页」未与表格右缘对齐 | 页眉右锚点用默认 ~555pt | Profile `page_header_right_x1` / `summary_page_header_right_x1` = 519.34（DSA 表格外框） |
| 报告编号行与正文不一致 | 页眉重写顺序或编号串入项目名 | `rewrite_merged_report_page_headers` + `_sanitize_report_no_for_header` |

## 三、多现场记录合并（DSA：JS-001 + JS-117）

| 现象 | 根因 | 修复 |
|------|------|------|
| §1.3 CBCT 出现 393、350 等 JS-001 数值 | `dynamicData.f24` 被 JS-001 污染，覆盖显式映射 | `normalize_template_bind_key` + `_resolve_submit_payload_for_site_task` 按 `siteTaskCode`/js 编号匹配 payload |
| 显式映射仍取错提交 | `templateId` 后缀 `.json-终` 导致模板键匹配失败 | `normalize_template_bind_key` 循环剥离后缀 |
| 合并时 f 号串位 | 多模板共用 f 号 | 显式映射优先；`apply_report_site_field_map` 多份 payload 隔离 |

## 四、工作场所放射防护表（§1.4）

| 现象 | 根因 | 修复 |
|------|------|------|
| 检测条件行缺失 | 提交 JSON 无含 kV 的整段条件文案；槽位仅为校准因子 | 模拟提交 `_inject_mock_rp_condition_line`；builder `_compose_rp_condition_template_line` 过滤校准因子 |
| 检测条件出现 0.98kV、0.85kV | 校准因子误入 kV/mA 槽 | `_looks_like_calibration_token` / `_looks_like_kv_value` |
| 位置列 `右侧_测量读数MμSv/h_...` | `_resolve_binding_location` 优先用测量列 field id | 优先 `loc_index`；`_sanitize_rp_location_sub` |
| 本底值为空 | 现场本底格为 `/` 或布尔；模拟未填本底读数 | `mock_inspection_submit_generator._fill_rp_background_level_mock`；builder 禁止 f641–f650 假扫描 |
| 报出值/本底为 `/`（模拟） | 表前因子 f106 未填；本底被划除 | 模拟：表前因子、本底、`_finalize_rp_chapter_supplemental_values` |
