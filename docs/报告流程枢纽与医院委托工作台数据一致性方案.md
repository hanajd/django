# 报告流程枢纽与医院/委托/工作台数据不一致：原因分析与统一方案

**状态：** 方案稿（仅分析与设计，**不改代码**）  
**日期：** 2026-07  
**相关页面：** 医院信息管理、项目工作台、委托管理、原始记录查看、报告生成及预览（及共用枢纽树的审核签发 / 报告导出及下载）

---

## 0. 一句话结论

五套界面**不是同一份「可见项目列表」**，而是各自按「权限集合 × 叶子是否存在 × 医院挂载键」组装视图：

| 页面 | 本质 |
| --- | --- |
| 医院信息管理 | **组织主数据**（医院/院区/科室/设备）；侧栏「关联项目」另有一套窄查询 |
| 项目工作台 | **配置态委托**（立项、挂设备、派工） |
| 委托管理 | **配置态 + 流程进度**（设备×任务、阶段） |
| 原始记录查看 | **有现场记录文件**的委托树 |
| 报告生成及预览 | **待编制进度**或**已有报告文件**的委托树（按 Tab） |

用户看到「对不上」，多半不是库坏了，而是**展示契约不同**；再叠加医院挂载键与权限公式不一致，就会放大偏差。

---

## 1. 各页数据源对照

| 页面 | 入口 | 项目基集 | 叶子/内容 | 空委托是否出现 |
| --- | --- | --- | --- | --- |
| 医院信息管理 | `/files/hospital-info/` | 组织树=全部活跃组织；关联项目=`commission_org_id=医院根` | 联系人、设备、报告绑定 | 组织始终可见；项目选项可能丢「挂科室」的委托 |
| 项目工作台 | `/files/projects/` | 活跃项目；「仅本人」时仅 `library_user_scoped_project_ids`（分配/创建/负责人，**不含**流程岗位成员） | 组织树挂项目、设备卡、任务 | **是** |
| 委托管理 | `/files/commission-manage/` | `commission_accessible_project_ids`（scoped **+ WorkflowMember**），上限约 500 | 设备×任务进度 | **是** |
| 原始记录查看 | `/files/hub/site-records/` | 同委托可访问集，枢纽再 `[:120]` | **仅** `site_record` 文件 | **否**（零叶子整委托隐藏） |
| 报告生成 · 编制 | `/files/hub/report-generate/?tab=generate` | 同上 | 进度叶子且阶段≈待编制 | **否**（无待办隐藏） |
| 报告生成 · 预览 | `?tab=preview` | 同上 | **仅**报告 PDF | **否**（无报告文件隐藏） |

关键实现位置：

- 枢纽树：`apps/core/workflow_hub_service.py`（`_accessible_projects`、`build_hub_browse_tree`）
- 委托可见集：`apps/core/commission_management_service.py`（`commission_accessible_project_ids`）
- 医院关联项目：`apps/core/hospital_info_service.py`（`projects_for_org_binding`）
- 工作台列表：`apps/core/views.py` → `library_projects`
- 权限 scoped：`apps/core/library_access.py`（`library_user_scoped_project_ids`）

## 2. 可能原因清单（按发生率排序）

### A. 展示契约不同（最常见，属产品预期偏差）

- **工作台 / 委托**：列「已立项」的委托（可无现场 PDF、未到报告阶段）。
- **原始记录**：只列已有 **现场记录文件** 的委托；仅 App 提交 JSON、未导出现场 PDF → 枢纽空白。
- **报告生成 · 编制**：只列流程进入「报告编制 / 待编制」附近的进度项；现场填报阶段在委托有、枢纽无。
- **报告生成 · 预览**：只列已有 **报告 PDF** 的委托。

→ 同一医院下「工作台很多、原始记录/报告生成很少」在当前实现下是**预期行为**，但 UI 未说明。

### B. 枢纽主动隐藏「零叶子」委托

`build_hub_browse_tree`：`leaf_count == 0` 则跳过整条委托（深链指定 `project_id` 除外）；报告编制 Tab 再要求 `attention_n > 0`。

→ 配置完整但无文件 / 未到阶段的项目，在枢纽「消失」。

### C. 可见项目权限公式不一致

| 角色场景 | 工作台（仅本人） | 委托 / 枢纽 |
| --- | --- | --- |
| 有任务分配 / 创建者 / 主要负责人 | 有 | 有 |
| **仅**流程岗位成员（WorkflowMember） | **无** | **有** |
| 可分配 / 管理员 | 全量活跃 | 全量活跃 |

→ 同账号在工作台与委托/枢纽看到的委托集合可差一截。

### D. 医院挂载键不一致

- 工作台：项目可挂在 **医院 / 院区 / 科室** 任一 `commission_org_id`。
- 枢纽按医院分组：用 `commission_org.hospital_root()`，一般仍能归到医院。
- 医院信息「关联项目 / 合并报告候选」：`projects_for_org_binding` **只查** `commission_org_id == 医院根 pk`。

→ 项目挂在科室时：工作台/枢纽能见，医院信息侧栏「关联项目」可能 **对不上甚至为空**。

### E. 原始记录 = 文件树，委托 = 进度树

- 委托管理叶子来自 `project_equipment_cards` + `InspectionSubmission`（设备×任务进度）。
- 原始记录叶子来自 `LibraryFile.CATEGORY_SITE_RECORD`（再过 `library_file_access_allowed`）。

→ 「委托里有进度、原始记录没有」：常见于未导出现场 PDF，或文件 ACL 挡掉。

### F. 报告生成 = 阶段过滤 + 文件过滤

- 编制 Tab：`STAGE_REPORT_DRAFT` 或目标阶段 `REPORT_AUDIT` 等「待编制」注意力过滤。
- 预览 Tab：只要报告分类文件。

→ 与委托全阶段列表天然不一致。

### G. 列表上限不同

- 枢纽：`commission_projects_queryset` 后再 **`[:120]`**。
- 委托：约 **`[:500]`**。
- 工作台：无同等切片（仅本人时按 scoped）。

→ 委托很多时，枢纽可能截断，表现为「少一批项目」。

### H. 文件二次 ACL

枢纽 `_file_rows` 对每份文件再跑 `library_file_access_allowed`。「仅本人文件」策略下，他人上传但挂在本项目的现场记录可能不可见 → 叶子变空 → 再触发 B。

### I. 设备归属靠文件名启发式

枢纽把文件名模糊匹配到 `equipment_title`；对不上进「其他」。工作台用 `LibraryProjectEquipment` 精确绑定。

→ 同一项目下设备分组名与工作台不一致，或文件堆在「其他」。

### J. 停用 / 软删 / 撤销

- `LibraryProject.is_active=False`：工作台/委托/枢纽通常都不列。
- 组织/设备停用：医院树消失，历史项目仍可能挂旧 org。
- 文件 `deleted_at`：只影响枢纽叶子。
- `LibraryProjectUserRevocation`：挡上传/写，**一般不**从各页项目列表剔除。

### K. 「医院」展示对象不同

- 医院信息：全部活跃组织（含无项目医院）。
- 枢纽：仅「有合格叶子」的医院根。
- 工作台：全组织树 + 可见项目挂接点。

→ 医院数量/名称集合也会对不齐。

## 3. 数据权威关系（当前事实模型）

```text
CommissionOrganization（医院 → 院区 → 科室）
        │
        ├── CommissionOrgEquipment（医院信息维护的设备主数据）
        │
        └── LibraryProject.commission_org_id（可挂任意层级）
                    │
                    ├── LibraryProjectEquipment（工作台：项目×设备×检测类型）
                    ├── library_tasks / 任务序号 task_no
                    ├── InspectionSubmission → InspectionCase → WorkflowState
                    └── LibraryFile ←→ LibraryFileProject
                              category: site_record | report | …
```

| 关系 | 权威写入 | 主要读取 |
| --- | --- | --- |
| 医院/院区/科室 | 医院信息管理 | 工作台树、枢纽医院分组、文件库路径 |
| 设备主数据 | 医院信息管理 | 工作台可选设备、委托进度卡 |
| 委托项目 | 项目工作台 | 委托、枢纽、API |
| 项目↔设备 | 项目工作台 | 进度、导出、枢纽进度叶 |
| task_no / 阶段 | 提交与流程推进 | 委托、报告生成/审核 |
| 现场记录 / 报告文件 | 导出/合并写入文件库 | 原始记录、报告预览/下载、医院合并绑定 |

**没有**统一的「页面项目目录」表或服务；各页各自组装。

## 4. 统一方案（拟定，待评审后再实现）

### 4.1 目标

1. **同一用户、同一时刻**：工作台 / 委托 / 枢纽的「基础可见项目集合」公式一致（或差集可解释、可开关）。
2. 医院维度：关联查询与分组一律按 **医院子树**，不再只认医院根精确 FK。
3. UI 契约写死：配置页显示「空壳」；枢纽默认显示「有料」，并提供「显示全部」以免被当成丢数。
4. 单一查询内核，避免再复制三套 `filter(is_active)` + 权限逻辑。

### 4.2 单一查询内核（建议新建服务层，例如 `ProjectCatalogService`）

```text
visible_projects(user, purpose) =
    BaseVisibility(user)          # 与委托管理对齐：scoped ∪ WorkflowMember ∪ 管理员全量
  ∩ is_active
  ∩ PurposeFacet(purpose)         # 仅裁剪/标注，不改 Base
```

| purpose | Facet 行为 |
| --- | --- |
| `workbench` / `commission` | 不因无文件隐藏；可加搜索/完成状态 |
| `hub_site_records` | 默认：有未删现场记录；可选：仍列出空委托并标「0 份」 |
| `hub_report_generate` | 编制：待办阶段；预览：有报告文件；可选「显示全部」 |
| `hub_review_sign` | 待审核/待签发注意力 |
| `hospital_binding` | 医院子树下全部活跃项目（修挂载键） |

工作台「仅本人」：改为调用同一 `BaseVisibility`，或在文档/UI 明确「工作台故意不含仅流程岗」并与委托对齐二选一（**推荐对齐**）。

### 4.3 医院键统一

- 展示医院：一律 `hospital_root()`。
- 关联查询：`commission_org_id ∈ subtree(hospital)`（或项目表冗余 `hospital_id`，写入时维护）。
- **废弃** `projects_for_org_binding` / 同类「仅医院根 pk」精确匹配。

可选落库：

```text
LibraryProject.hospital_id  → 指向 CommissionOrganization(医院根)
写入/变更 commission_org 时同步 hospital_id
```

便于索引与医院信息侧栏，避免每次扫子树。

### 4.4 页面展示契约（产品规则）

| 页面 | 空壳委托（无文件/未到阶段） |
| --- | --- |
| 医院信息 | 组织始终可见；关联项目=子树下全部活跃委托 |
| 工作台 / 委托管理 | **显示**（配置源） |
| 原始记录 | 默认隐藏；提供「显示无记录委托」或医院下角标「0 份仍列出」 |
| 报告编制 | 默认仅待办；提供「显示全部委托」 |
| 报告预览 / 下载 | 默认仅有报告者；可占位「尚未生成」 |

契约一旦定稿，页面文案应写清（例如：「此处仅显示已有现场记录 PDF 的委托」）。

### 4.5 叶子与设备绑定

- 进度叶子：继续共用 `build_commission_project_item_progress`，枢纽只做 purpose 过滤。
- 文件叶子：逐步用 `task_no` / 项目设备元数据归属，弱化文件名模糊匹配。
- 原始记录是否接受「仅有 JSON、无 PDF」：产品拍板后写入 Facet（可并列展示提交 JSON，或引导先导出现场 PDF）。

### 4.6 上限与运维

- 枢纽 `120` 与委托 `500` 统一策略（分页或提高上限，并在 UI 提示「仅显示前 N 条」）。
- 运维 Diff（按 user）：

```text
workbench − hub_site   → 分桶：no_site_file / acl_denied / over_limit / inactive
commission − hub_gen   → wrong_stage / no_attention
hospital_binding − workbench → org_fk_not_root / subtree_missing
```

上线前后用同账号跑 Diff，作为回归清单。

### 4.7 建议实施顺序（仍不在本轮改代码）

1. **文档/文案**：先在枢纽页标明「仅显示有记录/待编制/已生成报告的委托」。
2. **修医院挂载键**：`projects_for_org_binding` 改子树（或 `hospital_id`），与工作台对齐。
3. **抽 `ProjectCatalogService`**：工作台「仅本人」与委托 Base 对齐。
4. **枢纽 Facet +「显示全部」开关**：消除「以为丢了」的体验。
5. **文件归属元数据**：减少「其他」设备桶。
6. **Diff 脚本 / 管理命令**：持续监控集合差。

## 5. 排查时建议对照的检查项

对「某个具体委托在 A 有、B 无」：

1. 项目 `is_active`？挂在哪级 `commission_org`？
2. 当前用户：是否仅 WorkflowMember / 仅本人文件？
3. 是否有未删的 `site_record` / `report` 文件？是否被 ACL 过滤？
4. 流程阶段是否满足报告编制注意力条件？
5. 是否落在枢纽 120 截断之外？
6. 医院信息侧栏是否因「只认医院根」漏掉科室挂载项目？
