# 动态表单：后端对齐说明与建议前端调整

后端已按《动态表单 - 公式、判定、仪器选择功能说明》做了**部分对齐**（见 `utils/dynamic_form_expression.py` 与 `apps/api/inspection_report_make.py`）。本文说明**已实现范围**与**建议前端或模板侧配合**之处。

---

## 一、后端已实现

### 1. 表达式安全求值（与前端子集对齐）

- 模块：`utils/dynamic_form_expression.py`
- 能力概要：
  - 算术：`+ - * / % //`（`~/` 会预处理为 `//`）
  - 比较：`== != < <= > >=`
  - 逻辑：`and or not`（源码中的 `&&` `||` 会替换为 Python 运算符）
  - 三元：`a if b else c`（**见下文：Dart 风格 `?:` 未支持**）
  - 字面量：`true/false/null` → `True/False/None`
  - 命名空间：`constants.xxx`、`values.xxx`（与裸字段名等价）、`row.xxx`（**矩阵行内公式见下文**）
  - 函数：`avg` `sum` `min` `max` `abs` `round` `coalesce` `isEmpty` `len` `parseNum` `toBool` `unitFactor` `lookup` `ctdiw`
  - 前端函数 **`if(a,b,c)`**：在 Python 中 `if` 为关键字，后端将 **`if(` 预处理为 `__if__(`** 再求值，语义与前端一致。

### 2. 报告回填：`verdict.rule`

- `_attach_step_schema_to_pdf_fields` 会把 steps 中控件上的 **`rule` / `passLabel` / `failLabel` / `dependsOn` / `formula` / `type` / `label`** 合并到 PDF 坐标字段上。
- `_auto_verdict_text_if_applicable` **优先**对非空 `rule` 调用 `evaluate_verdict_rule`；为 `True`/`False` 时分别输出 `passLabel`（默认「合格」）与 `failLabel`（默认「不合格」）。
- 若 `rule` 无法求值或为空，**仍走原有**「判定标准文本 + 检测结果数值」逻辑（`verdict_from_criterion`）。

### 3. `computed` 补缺写入 `value_mapping`

- 在 `_fill_template_fields_with_submit_enhanced` 中，于 `_prepare_backfill_value_mapping` 之后调用 `_apply_computed_fields_from_steps_to_mapping`。
- 仅当 **`value_mapping[fieldId]` 仍为空** 且公式中**不含 `row.`** 时，用 `formula` 计算并写入，便于后续 PDF 占位符按 id 取值。
- **含 `row.*` 的矩阵单元格公式**当前不计算（需行上下文），依赖前端提交已写入的数值/报出值。

### 4. `instrument_select` 展示

- 若字段 `type` 为 `instrument_select` 且提交值为仪器 **id**，后端在写入 PDF 文本前尝试用 `source_data.instruments[]` 中的 `id` / `identifier` / `instrumentId` 匹配，替换为 `name` / `instrumentName`。
- 若列表缺失或匹配失败，**仍显示原 id**。

### 5. 模板常量 / 枚举 / 查表

- `_build_filled_template_fields_for_task` 会从模板 `formSchema`（或根级）读取 **`constants`、`enums`、`lookupTables`**，传入表达式求值与 `verdict.rule`。

## 二、建议前端或模板 JSON 的调整

### 1. 空合并运算符 `??`

- 后端 **未实现** `a ?? b` 语法解析。
- **建议**：在需服务端可算的模板中改写为 **`coalesce(a, b)`**（或链式 `coalesce`），与后端已实现函数一致。

### 2. Dart 风格三元 `condition ? a : b`

- 后端 AST 按 **Python** 解析，请使用 **`a if condition else b`**，或在仅前端展示的场景保留 Dart 写法（服务端不算）。
- **建议**：若同一 `rule` / `formula` 需前后端双算，统一为 **Python 三元**。

### 3. `unitFactor` 单参数调用

- 当前实现为 **`unitFactor(value, enumName)`**，`enumName` 缺省时无法定位枚举表。
- **建议**：模板中写全，例如：  
  `unitFactor(kermaTypicalUnit, "kermaUnit")`  
  与 `formSchema.enums` 中的表名一致。

### 4. 矩阵 `row.*` 公式

- 服务端不解析行上下文时，**含 `row.` 的 `computed` 不会在 `value_mapping` 中补缺**。
- **建议**：矩阵内计算、判定仍以前端为准并写入提交 JSON；或后续与后端约定「按行展开」的扁平 id 命名，再扩展服务端行上下文。

### 5. `instruments` 提交结构

- 仪器展示解析依赖 **`source_data["instruments"]` 为对象数组**，元素含 `id`（或 `identifier`）与 `name`（或 `instrumentName`）。
- **建议**：任务详情/提交聚合接口保证与前端文档一致；若实际键名不同，请与后端再对齐字段名或增加别名。

### 6. `lookupTables` 存放位置

- 后端读取顺序：`formSchema.lookupTables` → 根模板 `lookupTables`。
- **建议**：与 `constants` / `enums` 一并放在 **`formSchema`** 下，避免遗漏。

## 三、与《单项判定》文档的关系

- PDF 传统列「单项判定」仍以 **判定标准句 + 数值** 为主；若同一域在 steps 中配置了 **`type: "verdict"` + `rule`**，则 **rule 优先**。
- 详细数值比较语法仍见 `docs/报告单项判定规则与逻辑.md` 中的 `verdict_from_criterion` 一节；**表达式型 `rule`** 由 `dynamic_form_expression` 负责。
