# 模板编辑器结构校对改造说明

本文档记录本次对 HTMLPDF 模板编辑器的改造，目标是降低复杂表格模板制作时的人工命名成本。

## 1. 改造目标

原流程主要依赖人工把字段命名成：

```text
高对比度分辨力_检测结果
高对比度分辨力_报出值
```

这在字段数量达到几百、几千个时维护成本很高，也容易出错。本次改造后，模板制作不再强依赖人工手写下划线字段名，而是改为：

1. 自动识别 PDF 表格、行列、字段角色。
2. 编辑器保留结构化语义信息。
3. 人工纠错时只校对“检测项目 / 字段角色 / 子项”，不直接写字段名。
4. 导出前端 JSON 时由系统自动生成字段 ID、分组、`source.key` 和 `submitPath`。

## 2. 涉及文件

### 2.1 自动识别层

文件：

- `htmlpdf/full_text_coordinate_boxing.py`

改动：

- 自动识别字段结果新增 `autoSemantic`。
- `autoSemantic` 会尽量保留以下结构信息：
  - `tableId`
  - `row`
  - `col`
  - `cellId`
  - `itemName`
  - `typeName`
  - `fieldName`
  - `tailName`
  - `underlinePartName`
  - `slotNo`
  - `cellNameProbe`
  - `underlineSlot`

作用：

- 自动识别不再只输出一个中文字段名。
- 后续导出规则可以直接使用表格结构语义，而不是解析下划线字符串。

### 2.2 HTMLPDF 服务层

文件：

- `apps/core/htmlpdf_service.py`

改动：

- `htmlpdf_auto_red_text_fields_for_editor()` 返回编辑器字段时保留 `autoSemantic`。
- 同时继续保留旧字段：
  - `placeholder`
  - `originalPlaceholder`
  - `fieldType`
  - `checkboxPair`
  - `judgmentCriterionText`

作用：

- 自动框选接口 `/files/htmlpdf/api/auto-red-text-boxes/` 可以把结构化语义传给前端编辑器。

### 2.3 编辑器前端

文件：

- `htmlpdf/templates/index.html`

改动：

- 侧栏新增“结构校对”面板。
- 支持对当前选中框设置：
  - 检测项目/分组
  - 字段角色
  - 子项/单位/点位
- 新增操作：
  - `应用到选中框`
  - `同页同列套角色`
  - `结构重命名`
  - `结构预检`
- 编辑器导入、保存、自动命名同步时保留：
  - `autoSemantic`
  - `judgmentCriterionText`
  - `title`

作用：

- 人工纠错时不再需要写 `xxx_检测结果`。
- 只需要改结构字段，系统自动生成可导出的语义字段名。
- “同页同列套角色”用于批量处理表格列，例如把同一列批量设为“报出值”。

### 2.4 前端 JSON 规则导出层

文件：

- `utils/frontend_schema_rule_engine.py`

改动：

- 新增自动语义优先逻辑：
  - `_classify_by_auto_semantic()`
  - `_auto_semantic_field_id_label()`
  - `_AUTO_SEMANTIC_FIELD_ID_MAP`
- `build_frontend_schema_by_rules()` 中，字段分组优先级调整为：
  1. `autoSemantic`
  2. 下划线命名规则
  3. 中文语义兜底规则
- 带 `autoSemantic` 的字段会写入：
  - `source.autoSemantic`
  - `source.hierarchyKey`
  - `source.key`
  - 唯一 `source.submitPath`

作用：

- 自动结构字段可以直接导出为前端动态表单 schema。
- 多个“检测结果”“报出值”不会再统一挤到 `testResult.measuredValue` 或 `testResult.reportValue`。

## 3. 新数据结构

自动识别字段示例：

```json
{
  "page": 2,
  "x": 120.5,
  "y": 300.2,
  "w": 42.0,
  "h": 16.0,
  "placeholder": "高对比度分辨力_检测结果",
  "fieldType": "text",
  "autoSemantic": {
    "tableId": 1,
    "row": 3,
    "col": 4,
    "cellId": "t1_r3_c4",
    "itemName": "高对比度分辨力",
    "typeName": "检测结果",
    "fieldName": "高对比度分辨力_检测结果"
  }
}
```

导出前端 JSON 后，字段会生成类似：

```json
{
  "id": "measuredValue",
  "type": "number",
  "label": "检测结果",
  "source": {
    "pdfFieldId": "f12",
    "key": "step_qc_items.sec_xxx.t1_r3_c4.measuredValue",
    "submitBucket": "testResult",
    "submitPath": "testResult.auto.xxx.t1_r3_c4.measuredValue",
    "autoSemantic": {
      "tableId": 1,
      "row": 3,
      "col": 4,
      "itemName": "高对比度分辨力",
      "typeName": "检测结果"
    }
  }
}
```

## 4. 使用流程

### 4.1 自动生成初稿

1. 上传 PDF 模板。
2. 点击“按红字自动框选”。
3. 系统自动生成填写框，并尽量识别表格结构。

### 4.2 结构校对

选中任意填写框后，在左侧“结构校对”面板中填写：

- 检测项目/分组：例如 `高对比度分辨力`
- 字段角色：例如 `检测结果`、`报出值`、`检测条件`
- 子项/单位/点位：例如 `kV`、`20cm（足部）`

然后点击：

- `应用到选中框`：只修改当前字段。
- `同页同列套角色`：给同一页同一列的字段批量设置角色。
- `结构重命名`：按结构自动刷新字段名。
- `结构预检`：检查结构缺失、重名等问题。

### 4.3 导出前端 JSON

点击“保存前端规则 JSON”时：

1. 编辑器会保留并提交 `autoSemantic`。
2. 后端规则导出优先按 `autoSemantic` 分组。
3. 自动生成前端动态表单字段、提交路径和 PDF 绑定。

## 5. 与旧流程兼容性

本次改造保持兼容：

- 旧的下划线命名仍然可用。
- 手工修改字段标签仍然可用。
- 旧模板 JSON 没有 `autoSemantic` 时，仍走原规则导出逻辑。
- 自动识别失败时，可以用结构校对面板手工补结构。

## 6. 当前已验证

已完成以下检查：

- Python 源码语法编译通过。
- 编辑器内联 JavaScript 语法检查通过。
- 使用带 `autoSemantic` 的样例字段验证：
  - 能自动进入“质控检测项目”对应 section。
  - 能生成唯一 `source.key`。
  - 能生成唯一 `submitPath`，避免多个同名角色覆盖。

## 7. 当前边界

本次是“结构校对第一版”，还不是完整的可视化表格设计器。

当前已经解决：

- 不必逐框写下划线字段名。
- 可以按结构校对字段。
- 可以批量给同页同列套角色。
- 导出时能使用结构语义生成前端字段。

仍建议后续继续做：

1. 表格视图校对  
   把识别结果直接显示为表格，而不是只显示字段列表。

2. 多选批量操作  
   支持框选一批字段后统一设置检测项目或字段角色。

3. 低置信度队列  
   自动识别后只提示“疑似错误项”，减少人工逐项检查。

4. matrixTable 自动生成增强  
   对 DSA 点位类表格，直接生成 `matrixTable`，减少普通字段数量。

5. 字段结构预检增强  
   增加缺坐标、重复 `pdfFieldId`、重复 `source.key`、未绑定判定标准等检查。

## 8. 总结

本次改造把模板制作从“字段名驱动”推进到“结构驱动”：

- 以前：人工写字段名，规则引擎解析字段名。
- 现在：人工校对结构，系统生成字段名和绑定。

这能显著降低复杂表格模板的制作和校对成本，并为后续完整表格结构编辑器打基础。
