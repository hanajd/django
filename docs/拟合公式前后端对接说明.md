# 拟合公式（线性 / 对数 / 指数）前后端对接说明

本文档供 **模板编辑器 / 后台导出** 与 **Flutter 现场填表端** 对齐使用，使「曲线拟合公式 + R²」可按同一套 JSON 落地。

相关文档：

- `[json公式说明.md](./json公式说明.md)` — 通用公式与条件公式
- `[条件公式与前端type约定.md](./条件公式与前端type约定.md)` — `type: computed` 与公式下拉

**试点模板：** DR 验收现场记录（`001-验收检测/02-DR/...`）。  
**状态：** 约定已定稿；实现按本文分端落地。

---

## 0. 一句话结论


| 谁            | 做什么                                              |
| ------------ | ------------------------------------------------ |
| **后台 / 编辑器** | 只配置「如何拟合」：点列栏位、条件、拟合类型、公式格 ↔ R² 格配对；**不计算系数**    |
| **前端**       | 拿到现场 X/Y 数据后做最小二乘，写出方程（LaTeX）与 R²，用 MathJax 展示方程 |


后台没有实测读数，模板 JSON 里**不会出现**带数字的最终方程。

---

## 1. 业务目标

1. 模板编辑器配置一组或多组曲线拟合。
2. 拟合类型仅三种：`linear` / `log` / `exp`。
3. 用哪种类型：由现有 **条件公式**（`formulaRules[].condition`）决定，与报出值条件公式同一套交互。
4. 两个输出栏位：
  - **拟合公式格**：展示方程（前端 MathJax；成稿时再按源码渲图贴 PDF）。
  - **R² 格**：`type: number`，参与数值判定。
5. X、Y 在编辑器里用 PDF 点选多选（复用公式选栏逻辑）；顺序一一配对。

---



## 2. 数学模型（前后端共用）


| `fitKind` | 模型             | 约束            |
| --------- | -------------- | ------------- |
| `linear`  | y = ax + b     | 有效点对数 ≥ 2     |
| `log`     | y = a\ln x + b | 每个用于拟合的 x > 0 |
| `exp`     | y = a{\rm e}^{bx}（底数 e 正体，见 §6.4） | 每个用于拟合的 y > 0 |


**R²：** 对选定模型，在原始 (x_i,y_i) 上按常见定义计算（线性在 x-y；对数/指数在对应变换后拟合，再在原空间或变换空间统一一种定义——**前后端必须同一实现**，见 §6.3）。

**系数显示精度（建议）：** 小数点后 3～4 位；前后端用同一舍入规则，避免预览与提交不一致。

---



## 3. 栏位角色与配对



### 3.1 一对拟合 = 一主一从


| 角色        | 典型 type    | 存什么                                                |
| --------- | ---------- | -------------------------------------------------- |
| **公式主格**  | `computed` | 完整配置：`fitBinding` + 带 `fitKind` 的 `formulaRules`   |
| **R² 从格** | `number`   | 仅 `fitConfigRef` → 主格 `pdfFieldId`；**不**重复存 X/Y/条件 |


多组拟合 = 多对主从，配置互不共用。

```text
拟合 A:  f900 (主)  ←── fitConfigRef ──  f901 (R²)
拟合 B:  f910 (主)  ←── fitConfigRef ──  f911 (R²)
```



### 3.2 为什么 R² 必须是 `number`

- 现场要用数值做合格判定（如 `>=0.95`），判定写在 R² 格的 `judgmentCriteriaByTestType`。
- 按现有约定：`number` **不**渲染公式选择下拉；R² 由引擎自动写入，用户不选手动公式。
- 公式类型选择只发生在**主格**（`computed` + `formulaRules`）。



### 3.3 主格为什么是 `computed`

- 需要条件自动匹配，或多条空 `condition` 时人工下选「线性/对数/指数」。
- 与 `[条件公式与前端type约定.md](./条件公式与前端type约定.md)` 一致：有这类交互时导出必须 `type: "computed"`。

## 4. 模板 JSON 约定（后台写入 / 前端只读配置）

以下字段写在 `pdf.fields[]` 对应栏上，并随前端 schema 导出到绑定字段（与现有 `formulaRules` 同源路径）。

### 4.1 公式主格（完整样例）

```json
{
  "pdfFieldId": "f900",
  "type": "computed",
  "displayFormat": "latex",
  "fitBinding": {
    "x": ["f11", "f12", "f13", "f14"],
    "y": ["f21", "f22", "f23", "f24"],
    "r2FieldId": "f901"
  },
  "formulaRules": [
    {
      "id": "rule_fit_linear",
      "label": "线性",
      "condition": "f80==1",
      "fitKind": "linear"
    },
    {
      "id": "rule_fit_log",
      "label": "对数",
      "condition": "f80==2",
      "fitKind": "log"
    },
    {
      "id": "rule_fit_exp",
      "label": "指数",
      "condition": "f80==3",
      "fitKind": "exp"
    }
  ],
  "dependsOn": ["f11", "f12", "f13", "f14", "f21", "f22", "f23", "f24", "f80"]
}
```

说明：


| 键                           | 必填      | 说明                                                                         |
| --------------------------- | ------- | -------------------------------------------------------------------------- |
| `fitBinding.x` / `y`        | 是       | `pdfFieldId` 列表，**等长**；同下标为一对 (x_i,y_i)                                    |
| `fitBinding.r2FieldId`      | 是       | 本拟合对应的 R² 栏位                                                               |
| `formulaRules[].fitKind`    | 是（拟合规则） | `linear` | `log` | `exp`                                                   |
| `formulaRules[].condition`  | 否       | 与现有条件公式相同；非空则按序自动命中                                                        |
| `formulaRules[].label`      | 建议      | 下拉展示文案                                                                     |
| `formulaRules[].expression` | 否       | 拟合规则**可不写**算术表达式；若写哨兵 `fit_eq()`，前端见 `fitKind` 即走拟合分支，**勿**当 `avg(...)` 解析 |
| `displayFormat`             | 建议      | 固定 `"latex"`（或 `"markdown"` 且数学用 `$...$`）；告知 UI 用 MathJax，不当普通文本           |
| `dependsOn`                 | 建议导出补全  | X、Y、以及 `condition` 中引用的栏位                                                  |


**不要**在模板里写入带具体系数的 `equationLatex`。

### 4.2 R² 从格

```json
{
  "pdfFieldId": "f901",
  "type": "number",
  "fitConfigRef": "f900",
  "judgmentCriteriaByTestType": {
    "acceptance": ">=0.95",
    "status": ">=0.95"
  }
}
```


| 键              | 说明                                                    |
| -------------- | ----------------------------------------------------- |
| `fitConfigRef` | 主格 `pdfFieldId`；求值时去主格读 `fitBinding` + `formulaRules` |
| `type`         | 必须为 `number`（导出管线勿改成 `computed`）                      |




### 4.3 可选：展示模板（无系数）

若希望前后端拼串完全一致，可在主格或根级约定只读模板（系数用占位符）：

```json
"fitDisplayTemplates": {
  "linear": "y = {a}x + {b}",
  "log": "y = {a}\\ln x + {b}",
  "exp": "y = {a}{\\rm e}^{{b}x}"
}
```

注意：JSON 字符串里反斜杠需转义；解析后交给 MathJax 的是 `\ln`、`{\rm e}` 等。指数底数 **必须**用正体 `{\rm e}`，不要写成斜体变量 `e`。  
**不配时：** 前端按 §6.4 内置同一套模板即可。

### 4.4 条件选择策略（与现有一致）


| `formulaRules`       | 前端行为                                |
| -------------------- | ----------------------------------- |
| ≥1 条 `condition` 非空  | 按序求布尔，用**首个为真**的规则的 `fitKind`       |
| 多条且全部 `condition` 为空 | 主格下拉人工选（用 `label`）；选中后用该条 `fitKind` |
| 仅一条且 `condition` 为空  | 直接用该条 `fitKind`                     |


R² 格**从不**出现公式下拉。

### 4.5 `f` 号重排

编辑器侧栏重排 `pdfFieldId` 时，须 remap：

- `fitBinding.x` / `y` / `r2FieldId`
- `fitConfigRef`
- `formulaRules[].condition`（与现有公式 remap 相同）

## 5. 后台 / 编辑器实现清单



### 5.1 编辑器 UX（`htmlpdf`）

在公式编辑弹窗增加两个专用按钮：


| 按钮       | 行为                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------- |
| **拟合公式** | 当前栏作为主格；编辑 `fitBinding`（PDF 多选 X、多选 Y）；编辑带 `fitKind` 的条件规则；点选或指定 `r2FieldId`；写回主格并给 R² 格写 `fitConfigRef` |
| **R²**   | 当前栏 `type=number`；选择绑定哪个已有主格（多组时弹出列表）；只读展示摘要 +「去编辑主配置」；**禁止**再配一套 X/Y                                    |


PDF 点选：复用现有「公式选栏」叠加层，改为多选追加到 `x[]` 或 `y[]`。

校验建议：

- `x.length === y.length` 且 ≥ 2
- `r2FieldId` 未被其他拟合占用
- 主从互相指向一致（主格 `r2FieldId` ↔ 从格 `fitConfigRef`）



### 5.2 落盘与导出

- 保存坐标模板 JSON 时持久化 `fitBinding` / `fitKind` / `fitConfigRef` / `displayFormat`。
- 导出前端 schema 时原样带到绑定字段；主格保持 `type: computed`；R² 保持 `type: number`。
- **不要**在导出管线里对拟合主格跑普通 `fieldExpression` 求值并写成数字。
- `dependsOn`：由 `fitBinding` 与各 `condition` 引用自动汇总。



### 5.3 后台明确不做的事

- 不根据空数据算 a,b,R^2。
- 不在模板里预填带系数的方程。
- 不要求后台安装 MathJax 才能导出模板（渲染发生在前端展示 / 成稿阶段）。



### 5.4 成稿阶段（有提交数据之后）

现场提交答案后，服务端若生成 PDF/Word：

- 使用提交结果里的 `equationLatex`（或等价字段）与 R² 数值；
- PDF：MathJax（或等价）渲 SVG/PNG，以公式格 **rect 中心为锚点** 贴图（非必须塞进文本域）；
- Word：用 LaTeX/MathML **源码** 转 OMML，勿只依赖 PDF 位图。

成稿渲染属后续能力；**首期以编辑器配置 + 前端求值展示为准**。

## 6. 前端实现清单（Flutter）



### 6.1 识别拟合栏位

- 主格：存在非空 `fitBinding`（或规则带 `fitKind`）。
- 从格：存在 `fitConfigRef`。

普通 `formula` / `avg(...)` 路径与拟合路径分支，避免把 `fit_eq()` 当算术解析报错。

### 6.2 求值时机

当以下任一变化时重算该组拟合：

- `fitBinding.x` / `y` 任一栏位值变化；
- 影响 `condition` 的栏位变化；
- 用户手动切换了空 condition 下的规则。

步骤：

1. 解析主格 `formulaRules`，得到当前 `fitKind`（自动或手选）。
2. 按序读取 `x[i]`、`y[i]`，转为 `double`；跳过空/非数字对（或整组失败——**建议：有效对 < 2 则清空结果并提示**）。
3. 按 `fitKind` 做最小二乘 → `a`, `b`, `r2`。
4. 写主格展示结果 + 从格 R²。



### 6.3 算法约定（须前后端文档一致；实现只在前端）

以下为实现基准（可微调但须写进本表并锁定）：

**线性：**  
对 y = ax+b，普通最小二乘。

**对数：**  
令 X=\ln x，对 y = aX + b 线性最小二乘（要求 x_i>0）。

**指数：**  
对 y = a{\rm e}^{bx}，取 \ln y = \ln a + bx（要求 y_i>0），对 \ln y 与 x 线性回归得 b 与 \ln a，再 a={\rm e}^{\ln a}。展示时底数 e 用正体 `{\rm e}`（见 §6.4）。

**R²（建议统一用原空间）：**  
\hat y_i 由模型算出后，


R^2 = 1 - \frac{\sum (y_i-\hat y_i)^2}{\sum (y_i-\bar y)^2}


分母为 0 时约定结果为 `null` 或空，并提示。

### 6.4 生成展示字符串

内置模板（与可选 `fitDisplayTemplates` 对齐）：


| fitKind | `equationLatex`（解析后给 MathJax，无多余细空格） |
| ------- | ---------------------------------------------- |
| linear  | `y = {a}x + {b}`（若 b&lt;0 写成 `y = {a}x - {|b|}`） |
| log     | `y = {a}\ln x + {b}`（JSON 文件中 `\ln` 写作 `\\ln`） |
| exp     | `y = {a}{\rm e}^{{b}x}`（**e 必须正体** `{\rm e}`；JSON 中写作 `{\\rm e}`） |

另写纯文本 `value` 兜底，例如 `y = 1.234x + 0.567`（无 LaTeX 命令），供不支持公式的通道。指数纯文本可用 `y = 1.234*exp(0.567x)` 或 `y = 1.234e^(0.567x)`，与 LaTeX 正体要求无关。

### 6.5 运行时结果形态（答案 / 本地状态，非模板）

```json
{
  "f900": {
    "value": "y = 1.234x + 0.567",
    "equationLatex": "y = 1.234x + 0.567",
    "fitKind": "linear",
    "fitParams": { "a": 1.234, "b": 0.567 }
  },
  "f901": 0.998
}
```

提交给后台时至少保证：

- 主格能还原方程（`equationLatex` 或 `value`）；
- R² 为 number；
- 建议带上 `fitKind` / `fitParams` 便于审计与 Word 导出。

若现有提交协议是「栏位 id → 标量」，可约定：

- `f901` → `0.998`
- `f900` → 字符串 `equationLatex`（或 `value`）
- 扩展字段放在并行的 `fitResults.f900` 对象中（需与现有 submit schema 对齐时再定一种，**首期优先标量 + equationLatex 字符串**）。



### 6.6 UI

- 主格：`displayFormat == "latex"`（或识别到 `fitBinding`）时用 **MathJax**（或 Flutter 等价数学渲染）渲染 `equationLatex`；不要把原始配置 JSON 当正文显示。
- 多条空 condition：主格显示与现有 `computed` 相同的公式选择下拉（`label`）。
- R²：普通 number 展示 + 判定；只读或自动覆盖（与其它自动计算 number 一致）。
- 点数不足、x\le0（log）、y\le0（exp）：清空方程与 R²，给出可读错误，勿静默写错值。



### 6.7 依赖重算

将 `fitBinding.x/y` 与 condition 引用加入依赖图；任一变化触发该组主从一起更新（先写主格方程，再写 R²）。

## 7. 端到端数据流

```text
[编辑器]
  配置 fitBinding + formulaRules.fitKind + 主从绑定
  → 保存模板 JSON / 导出 formSchema
        ↓
[Flutter 加载模板]
  只拿到「怎么算」，没有 a、b、R²
        ↓
[现场录入 X/Y 及相关判定栏]
  → 命中 fitKind → 最小二乘
  → 写 equationLatex + R²
  → MathJax 展示方程；R² 参与判定
        ↓
[提交]
  答案中带方程字符串与 R²
        ↓
[后台成稿，可选后续]
  用提交的 LaTeX 渲图贴 PDF；Word 用源码插公式
```

## 8. 与现有公式体系的边界


| 能力                                        | 是否复用                    |
| ----------------------------------------- | ----------------------- |
| `formulaRules` 的 condition / label / 选择策略 | 是                       |
| `expression` 算术引擎（`avg`、`round`…）         | 拟合规则不走此路径               |
| PDF 点选栏位                                  | 是（扩展为多选列表）              |
| `judgmentCriteriaByTestType`              | R² 格照常使用                |
| `{mean}` 章节占位                             | 拟合不使用                   |
| 普通 `fieldExpression`                      | 主格有 `fitBinding` 时以拟合为准 |

## 9. 联调检查清单



### 后台 / 编辑器

- [ ] 主格可保存并再打开：`fitBinding`、`fitKind`、`r2FieldId` 不丢
- [ ] R² 格仅有 `fitConfigRef`，无第二份 x/y
- [ ] 多组拟合互不串改
- [ ] `f` 重排后引用全部更新
- [ ] 导出主格 `type=computed`，R² `type=number`
- [ ] 导出 JSON 中无带系数的假方程



### 前端

- [ ] 读到配置后，无数据时不报崩溃；有 ≥2 有效点才出结果
- [ ] 三种 `fitKind` 结果与约定算法一致（可用固定样例点对拍）
- [ ] 条件切换 / 手选规则后方程与 R² 一起变
- [ ] MathJax 渲染 `equationLatex`；线性式无多余 `\,`
- [ ] R² 可走 `>=0.95` 类判定
- [ ] 提交载荷含方程与 R²，后台能读到



### 样例点对（线性自测）


| x   | y   |
| --- | --- |
| 1   | 2   |
| 2   | 4   |
| 3   | 6   |


期望：a \approx 2，b \approx 0，R^2 \approx 1；  
`equationLatex` 类似 `y = 2x + 0` 或 `y = 2.000x + 0.000`（按约定精度）。
