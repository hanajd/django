# 业务线扩展评估（第三版）：医院信息立项 · 业务线预留

> **文档性质**：需求评估与方案草案（**尚未改代码**）  
> **修订日期**：2026-07-17（第三版）  
> **用途**：供产品/业务确认后，再按确认项落地开发  

---

## 0. 本版新增取向

| 项 | 说明 |
|----|------|
| **委托项目建立位置** | 放到 **医院信息管理** 下完成，对应并收敛当前「项目工作台 · 新建项目」与「委托立项」能力 |
| **业务线实现范围** | 后台 **当前只做检测报告线**；**预评价 / 控制效果评价** 先做 **业务线预留**（选型、字段、入口占位），功能后期再完善 |
| **继承第二版** | 销售不进系统；行政录入起点；两部门工作台操作；派单仅本部门；主任可建本部门用户 |

---

## 1. 修订后的主路径（行政视角）

```
线下签单
  →【医院信息管理】行政录入医院 / 院区 / 科室 / 设备
  →【医院信息管理】建立委托项目（自动编号 + 项目名）
       · 选择业务线：检测报告 | 预评价（预留）| 控制效果评价（预留）
       · 检测线：挂载设备与检测类型（现「委托立项」能力迁入/复用）
  → 提交到对应部门
  →【项目工作台】检测部 / 评价部：派单与后续
```

**项目工作台**不再作为「从零新建委托项目」的主入口（可保留入口但引导去医院信息，或仅管理员兼容）；工作台专注 **派单、仪器、进度、报告环节**。

---

## 2. 立项能力迁移：医院信息管理 ↔ 项目工作台

### 2.1 现状（拆开的两处）

| 位置 | 现有能力 |
|------|----------|
| **项目工作台 · 新建项目** | 三步向导：委托单位 → 设备与检测类型 → 可选统筹人；生成 `LibraryProject` |
| **项目工作台 · 委托立项** | 在已有项目上继续挂载设备 / 检测类型 / 报告模板 |
| **医院信息管理** | 医院树、设备台账；**尚无**完整建项向导 |

### 2.2 目标归并

| 能力 | 目标归属 | 说明 |
|------|----------|------|
| 录入医院/地址/设备 | 医院信息管理 | 已有，行政主责 |
| **新建委托项目** | **医院信息管理** | 承接工作台「新建项目」向导（或同款 UI 嵌在医院节点下） |
| **挂载设备与检测类型** | **医院信息管理（建项时）+ 必要时工作台补录** | 建项时完成主挂载；检测部后续若需增补，可在工作台「委托立项」保留补录（权限收窄） |
| 人员派单 | 项目工作台 | 仅本部门；主任操作 |
| 进度 / 报告环节 | 项目工作台 | 检测线现有流程；评价线后期 |

### 2.3 交互建议（MVP）

在医院信息管理中，进入某医院（或科室）详情后提供：

1. **「建立委托项目」** 按钮（行政 / 有建项权）  
2. 向导内容 ≈ 现 `project_create_modal`：选范围（默认当前医院树节点）→ 勾选设备与检测类型 → 选业务线 → 自动编号与项目名 → 提交到检测部或评价部  
3. 提交成功后：跳转或深链到 **项目工作台** 对应项目（检测部待派单队列）

工作台顶栏「新建项目」：改为「请到医院信息管理立项」提示，或隐藏（超管可保留兼容）。

## 3. 业务线：检测已实现 · 评价两条预留

### 3.1 三分叉（数据层立刻预留）

建议在 `LibraryProject`（或委托单）增加：

```text
business_line ∈ { inspection, pre_eval, control_effect }
```

| 值 | 名称 | 本期 | 后期 |
|----|------|------|------|
| `inspection` | 检测报告 | **完整可用**（现有现场→签发，再加归档） | 持续优化 |
| `pre_eval` | 预评价报告 | **仅预留**：可选、落库、工作台占位 | 评价状态机、产物、待办 |
| `control_effect` | 控制效果评价 | **仅预留**：可选、落库、占位；嵌套检测接口预留 | 子项目派单 + 评价流程 |

### 3.2 「预留」具体指什么（避免空壳误用）

| 层 | 预留内容 | 禁止/降级 |
|----|----------|-----------|
| **建项 UI** | 业务线下拉三选一；选评价线时提示「功能开发中，仅登记意向」或仍允许建项但标记 `line_status=reserved` | 不进入虚假的评价编制流程 |
| **数据** | `business_line` 必填；评价线项目可建，便于后期迁移 | 不伪造已完成评价报告 |
| **项目工作台** | 评价部队列可见「预评价 / 控制效果」卡片；详情页展示 **「评价流程即将上线」** 占位 | 不开放未实现的评审会/报送按钮（或灰显） |
| **派单** | 评价线项目：评价主任可先派本部门人（可选）；或本期评价线 **仅登记不派单** | 不要派到检测五岗冒充评价流程 |
| **检测线** | 照常派单与推进 | — |
| **接口/枚举** | 状态机枚举、文件分类、枢纽待办类型 **先定义常量与空分支** | 分支内 `NotImplemented` / 友好提示 |

### 3.3 控制效果「检测派单」预留

数据上预留：

- `parent_project_id`（子检测项目挂评价主项目）  
- 或 `needs_inspection_dispatch` 标记  

本期可不生成子项目；UI 上灰显「发起检测派单」。后期评价线完善时再接通。

### 3.4 与「当前只做检测」的产品表述

> 医院信息管理可登记三类业务意向；**流程与报告能力本期仅打通检测报告**。预评价、控制效果评价项目可先建档排队，功能上线后在同一项目上续作，避免后期再拆单。

若业务担心误用：建项时评价线改为「仅管理员可建」或「仅保存草稿意向单」——请在 §8 确认。

## 4. 部门 · 派单 · 主任建用户（沿用第二版）

| 规则 | 内容 |
|------|------|
| 部门 | 结构化：`admin_office` / `inspection` / `evaluation` |
| 派单 | **仅本部门员工**；后端强制校验 |
| 跨部协作 | 仅控制效果后期：「评价发起 → 检测主任再派」 |
| 主任 | 可创建 **本部门** 用户（部门范围用户管理） |
| 行政 | 医院信息 + 建项；不派现场岗 |

---

## 5. 检测线本期仍要做的增强（在预留之外）

即使评价线只预留，检测线建议同期完成或紧随：

1. 医院信息管理承接建项（含设备挂载）  
2. 行政角色 + 自动编号/项目名  
3. 部门字段 + 派单本部门过滤  
4. 检测部主任角色与工作台队列  
5. （可选同期）检测线 **归档** 状态  

评价部主任角色与评价队列占位：可与预留一起做，避免后期再改导航。

## 6. 分期（按「预留评价、做实检测」重排）

| 优先级 | 内容 |
|--------|------|
| **P0** | `business_line` 字段 + 建项三选一；评价线占位文案；**医院信息管理建项**（迁入新建项目+挂载设备）；行政角色；自动编号/项目名 |
| **P0** | `org_unit` + 派单本部门过滤 + 后端校验 |
| **P1** | 检测/评价主任；工作台按部门+业务线过滤；主任建本部门用户；工作台「新建项目」降级/引导 |
| **P1** | 检测线归档 |
| **P2** | 预评价完整流程（在预留骨架上填肉） |
| **P3** | 控制效果 + 嵌套检测派单 |

## 8. 仍需确认

1. 工作台「新建项目」： **隐藏**、还是保留并跳转医院信息？  
2. 建项后「委托立项」补录设备：检测部是否仍可在工作台增补？  
3. 选预评价/控制效果建项：允许正式建 `LibraryProject`，还是只建「意向草稿」？  
4. 评价线项目本期是否允许评价主任派本部门人，还是完全只读排队？  
5. 项目名公式、主任用户管理范围（本部门全部 vs 仅本人创建）——沿用第二版待选项。  
6. 控制效果检测报告编制方：仍建议检测部（后期）。  

---

## 9. 推荐结论（第三版）

1. **委托项目建立放在医院信息管理**，收敛工作台「新建项目 + 委托立项（主挂载）」能力。  
2. **项目工作台**专注部门内派单与后续；检测线全功能，评价线先占位。  
3. **数据与入口预留** `pre_eval` / `control_effect`，避免后期大搬家；本期不实现评价编制/评审会/报送。  
4. 派单本部门隔离、主任建本部门用户、行政录入起点——与第二版一致，优先落地。
