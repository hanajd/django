# Django 后台从零部署流程（交付计划）

> **文档性质**：交付/运维计划说明，**不改变当前仓库代码**。  
> **适用仓库**：`tablet_backend`（检测业务 Web 后台 + REST API）。  
> **默认端口**：`11223`（可用 `DJANGO_PORT` 覆盖）。  
> **关联文档**：[01-configuration.md](01-configuration.md)、[05-utils-and-pipelines.md](05-utils-and-pipelines.md)、[06-scripts-and-admin.md](06-scripts-and-admin.md)。

## 0. 交付形态建议（先选型）

| 形态 | 甲方是否易见源码 | 适用场景 | 说明 |
|------|------------------|----------|------|
| **A. 我方托管（SaaS / 专属云）** | 基本不可见 | 优先推荐 | 甲方只访问浏览器/App；源码与服务器在我方 |
| **B. 甲方机房部署（源码包）** | 可见 | 合同要求交源码 | 按本文「从零部署」落地；靠合同约束 |
| **C. 甲方机房部署（运行态交付）** | 显著提高门槛 | 要现场部署又不愿交源码 | 交付镜像/虚机/二进制包，见第 8 节 |
| **D. 混合** | 部分可见 | 常见 | 核心算法/管线我方服务；业务后台可现场部署 |

本文主体按 **形态 B/C 的「现场服务器从零安装」** 编写；第 8 节单独评估「让甲方看不到源码」的可行办法。

## 1. 系统组成（部署时要起的进程）

```text
                    ┌─────────────────┐
  浏览器 / 平板 App ──►│ Nginx（可选）    │
                    └────────┬────────┘
                             ▼
                    ┌─────────────────┐
                    │ Gunicorn/uWSGI  │  ← Django（WSGI）
                    │ + tablet_backend│
                    └────────┬────────┘
           ┌─────────────────┼─────────────────┐
           ▼                 ▼                 ▼
    SQLite/PostgreSQL   本地 media/        Ollama :11434
    （默认 SQLite）      file_library/      （OCR 管线结构化）
                              │
                              ▼
                         MinerU（Python 包，
                         由管线子进程调用）
                              │
                              ▼
                         Node.js + mathjax-full
                         （报告公式叠印，按需）
```

| 组件 | 是否必须 | 作用 |
|------|----------|------|
| Python 3.10–3.12 + Django | **必须** | Web / API |
| `media/`、字体 `htmlpdf/fonts/SIMSUN.TTC` | **必须** | 文件库、PDF 中文叠印 |
| Node.js + `npm` 依赖（mathjax） | 强烈建议 | `$$…$$` 公式渲染到 PDF |
| **Ollama** + 模型 `qwen3:14b-q4_K_M` | OCR/铭牌/前端模板辅助生成需要 | 默认 `OLLAMA_HOST=http://127.0.0.1:11434` |
| **MinerU**（`requirements.txt` 已含） | OCR 管线需要 | `MINERU_BACKEND` 默认 `pipeline` |
| NVIDIA 驱动 + CUDA | GPU 加速时需要 | MinerU / Ollama 共用显卡时注意显存调度 |
| Nginx | 生产建议 | HTTPS、静态/媒体反代、限流 |
| PostgreSQL | 可选 | 当前默认 SQLite；高并发/多机时建议换库（需改配置，本计划仅列项） |

**可降级说明**：不装 Ollama/MinerU 时，日常「文件库、工作流、报告导出、签名」等核心业务仍可用；**文档识别管线 / 铭牌抽取 / Ollama 辅助生成前端模板**不可用。

## 2. 硬件与环境基线（建议）

| 项 | 最低（业务演示，无 OCR） | 推荐（含 OCR + Ollama） |

## 3. 从零部署总流程（清单）

1. 准备操作系统与基础包  
2. 安装 NVIDIA 驱动（若用 GPU）  
3. 安装并启动 **Ollama**，拉取模型  
4. 创建 Python 虚拟环境，安装 `requirements.txt`（含 MinerU、ollama SDK）  
5. 安装 Node.js，执行 `npm install`（MathJax）  
6. 放置交付包（代码或运行态产物）与字体、初始 `media`  
7. 配置环境变量（生产密钥、`DEBUG=False` 等）  
8. `migrate`、种子数据、管理员账号  
9. 用 Gunicorn +（可选）Nginx + systemd 常驻  
10. 验收：Web 登录、API、PDF 导出、Ollama 连通、管线抽样  

预估工时（熟悉人员、有 GPU 机器）：**0.5～1.5 人日**；首次含驱动/模型下载视网络可达 **半天～1 天**。

## 4. 分步操作说明

### 4.1 操作系统与系统依赖

以 Ubuntu 为例：

```bash
sudo apt update
sudo apt install -y \
  build-essential git curl wget \
  python3 python3-venv python3-dev \
  poppler-utils \
  libgl1 libglib2.0-0 \
  fonts-dejavu-core
```

说明：

- `poppler-utils`：`pdf2image` 等 PDF→图依赖。  
- OpenGL/`libglib`：部分视觉/MinerU 依赖常见缺库。  
- 宋体主字体以仓库内 **`htmlpdf/fonts/SIMSUN.TTC`** 为准，须随交付包携带（勿依赖系统是否已装中易字体）。

**Node.js（建议 18+ / 20 LTS）**：

```bash
# 示例：NodeSource 或 nvm，按甲方环境规范二选一
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v && npm -v
```

### 4.2 GPU 驱动（可选但 OCR/Ollama 强烈建议）

1. 安装与显卡匹配的 NVIDIA 驱动，重启后 `nvidia-smi` 正常。  
2. 确认 Ollama / PyTorch（MinerU 依赖）能看见 GPU。  
3. 多卡时可用环境变量（见 `utils/gpu_scheduler.py` 注释）：  
   - `MINERU_CUDA_VISIBLE_DEVICES`  
   - `OLLAMA_PREFERRED_GPU_INDEX`  
   - `PIPELINE_GPU_AUTO_OLLAMA` / `PIPELINE_GPU_AUTO_MINERU`

### 4.3 安装 Ollama（必须：管线 AI 能力）

**在线安装（官方脚本，以当时文档为准）：**

```bash
curl -fsSL https://ollama.com/install.sh | sh
sudo systemctl enable --now ollama
ollama --version
curl -s http://127.0.0.1:11434/api/tags
```

**拉取本项目默认模型**（与 `utils/pipeline_config.py` 一致）：

```bash
# 可用环境变量覆盖：EQUIPMENT_MODEL_NAME
ollama pull qwen3:14b-q4_K_M
```

离线交付时：在可联网机器 `ollama pull` 后，按 Ollama 文档导出/拷贝模型目录（常见在 `~/.ollama/models`），再在甲方机导入。

**安全**：默认仅监听本机 `127.0.0.1:11434`。**不要**把 Ollama 端口裸暴露到公网；Django 通过 `OLLAMA_HOST` 访问即可。

**连通性自检：**

```bash
curl http://127.0.0.1:11434/api/tags
ollama run qwen3:14b-q4_K_M "回复：ok"
```

### 4.4 获取应用代码 / 运行包

- **形态 B**：将发布包解压到如 `/opt/tablet_backend/`（下文称 `$APP`）。  
- **形态 C**：解压/导入镜像后，工作目录以镜像说明为准（可能无 `.py` 源码树）。  

建议目录权限：专用系统用户 `tablet`，`$APP` 与 `media` 可写。

### 4.5 Python 虚拟环境与依赖

```bash
cd $APP
python3 -m venv .venv
source .venv/bin/activate
pip install -U pip wheel
pip install -r requirements.txt
```

注意：

- `requirements.txt` 含 `mineru`、`ollama`、`pymupdf` 等，体积大、编译久，首次安装建议预留时间。  
- 目标 Python：**3.10+**（文件头注释写 3.12.x；以甲方已验证版本为准）。  
- 若 MinerU 安装失败：可先保证 Django 主站可用，再单独排查 CUDA/torch；`MINERU_BACKEND` 默认 `pipeline`（避免 hybrid+vLLM 链路）。

### 4.6 Node 依赖（MathJax）

```bash
cd $APP
npm install
# 确认存在：node_modules/mathjax-full 、 scripts/mathjax_tex2svg.mjs（若仓库提供）
```

无 Node 时：含公式的报告叠印可能失败或降级，不影响整体登录与多数 PDF 填充。

### 4.7 环境变量（生产必配）

在 systemd 的 `Environment=` 或 `$APP/.env`（若用 python-decouple/自行加载）中设置，**至少**：

| 变量 | 示例 / 说明 |
|------|-------------|
| `SECRET_KEY` | 长随机串，**禁止**用仓库默认 insecure 值 |
| `DEBUG` | `0` / `False` |
| `DJANGO_PORT` | `11223`（若直连 Gunicorn 可改） |
| `ALLOWED_HOSTS` | 甲方域名/IP（当前代码若仍写死 `*`，部署前需在配置层收紧，见下） |
| `OLLAMA_HOST` | `http://127.0.0.1:11434` |
| `EQUIPMENT_MODEL_NAME` | `qwen3:14b-q4_K_M`（与已 pull 模型一致） |
| `OLLAMA_OPTIONS` | 可选 JSON，如 `{"num_gpu":999,"num_ctx":8192}` |
| `MINERU_BACKEND` | 默认 `pipeline`；有把握再用 `hybrid-auto-engine` |
| `CORS_ALLOWED_ORIGINS` | 仅 App/前端真实来源（生产勿过宽） |
| `JWT_ACCESS_TOKEN_HOURS` / `JWT_REFRESH_TOKEN_DAYS` | 按安全策略 |

> **配置现状提示（计划项，非本次改码）**：仓库 `settings.py` 开发默认 `DEBUG=True`、`ALLOWED_HOSTS=['*']`、SQLite。正式交付前应在发布分支或部署包装中固化生产配置，或通过环境变量完整覆盖；验收清单见第 7 节。

可选加固（演示账号）：`PARTY_A_DEMO_ALLOWED_IPS` 等，见 [01-configuration.md](01-configuration.md)。

### 4.8 数据库与初始化

当前默认：**项目根目录 `db.sqlite3`**。

```bash
cd $APP
source .venv/bin/activate
export DJANGO_SETTINGS_MODULE=tablet_backend.settings
# export SECRET_KEY=... DEBUG=0 ...

python manage.py migrate
python manage.py init_data                 # 角色/菜单种子
python manage.py createsuperuser           # 管理员
# 按合同需要：
# python manage.py ensure_party_a_demo
# python manage.py ensure_template_tester
```

生产静态文件：

```bash
python manage.py collectstatic --noinput
```

（若尚未配置 `STATIC_ROOT`，需在生产配置中补齐后再收集；计划阶段记为发布检查项。）

### 4.9 进程常驻（systemd 示例）

**Ollama**：安装脚本通常已带 `ollama.service`。

**Django（Gunicorn 示例）**：

```ini
# /etc/systemd/system/tablet-backend.service
[Unit]
Description=Tablet Django backend
After=network.target ollama.service
Wants=ollama.service

[Service]
User=tablet
Group=tablet
WorkingDirectory=/opt/tablet_backend
Environment=PATH=/opt/tablet_backend/.venv/bin
Environment=SECRET_KEY=请替换
Environment=DEBUG=0
Environment=OLLAMA_HOST=http://127.0.0.1:11434
Environment=EQUIPMENT_MODEL_NAME=qwen3:14b-q4_K_M
Environment=MINERU_BACKEND=pipeline
ExecStart=/opt/tablet_backend/.venv/bin/gunicorn \
  tablet_backend.wsgi:application \
  --bind 127.0.0.1:11223 \
  --workers 2 \
  --timeout 300 \
  --access-logfile /var/log/tablet/access.log \
  --error-logfile /var/log/tablet/error.log
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now tablet-backend
```

管线/PDF 可能较久，`--timeout` 建议 ≥300。工人数按 CPU/内存调整；**避免**与 Ollama 抢光显存。

**Nginx 反代（示意）**：对外 `443` → `127.0.0.1:11223`；`/media/`、`/static/` 直接 alias 到磁盘以减负。启用 HTTPS 证书。

### 4.10 数据与备份

| 对象 | 路径/说明 | 备份策略建议 |
|------|-----------|--------------|
| 数据库 | `db.sqlite3`（或未来 PostgreSQL） | 每日；可用 `manage.py backup_database` |
| 文件库 | `media/file_library/` | 与库同步备份 |
| 签名与用户上传 | `media/` 下其它目录 | 同上 |

## 6. 常见问题（部署期）

| 现象 | 方向 |
|------|------|
| PDF 中文方框/报 missing font | 检查 `htmlpdf/fonts/SIMSUN.TTC` |
| Ollama 连接失败 | `systemctl status ollama`、`OLLAMA_HOST`、防火墙 |
| 模型名不匹配 | `EQUIPMENT_MODEL_NAME` 与 `ollama list` 一致 |
| MinerU/CUDA 报错 | 驱动、PyTorch CUDA、改回 `MINERU_BACKEND=pipeline` |
| 显存 OOM | 降 `num_ctx`、限 `num_gpu`、错开管线与推理 |
| 公式不渲染 | Node/`mathjax-full`/`mathjax_tex2svg.mjs` |
| 权限 403 写 media | 运行用户对 `media/` 可写 |
| 启动慢/卡在媒体校验 | `LIBRARY_MEDIA_INTEGRITY_ON_STARTUP=0`（仅临时） |

## 8. 源码保护评估（甲方看不到源码？）

### 8.1 结论先说清楚

**Django 这类以 Python + 服务端模板为主的系统，无法在「把完整可运行系统交给甲方服务器、又完全不给任何可分析材料」的前提下做到密码学级保密。**  
能做的是：**提高获取成本**、**缩小交付面**、**用合同与架构把核心留在我方**。

Web 端仍会下发 HTML；API 行为可被抓包；有经验的人拿到字节码/镜像仍可能逆向。目标应定为「**正常运维与业务人员看不到、拷不走清晰源码树**」，而非「绝对不可逆向」。

### 8.2 方案对比

| 方案 | 甲方可见源码程度 | 实现成本 | 可维护性 | 推荐度 |
|------|------------------|----------|----------|--------|
| **① 我方托管（SaaS/专属 VPC）** | 几乎看不到 | 低～中（运维在我方） | 高 | **最推荐** |
| **② 现场部署虚机/一体机，无源码盘** | 默认看不到；root 仍可能掏镜像 | 中 | 中（需远程运维约定） | **推荐** |
| **③ Docker 镜像交付（不含源码层）** | 镜像层仍可能被 export 分析 | 中 | 中 | 可选 |
| **④ Nuitka / Cython 编译核心包** | `.py` 减少；模板/静态仍在 | 高 | 低（调试难） | 核心模块可试 |
| **⑤ PyArmor 等混淆** | 提高门槛，可破解 | 中 | 低 | 仅作辅助 |
| **⑥ 只发 `.pyc`** | 极易反编译 | 低 | 差 | **不推荐当主方案** |
| **⑦ 源码全交 + 合同保密** | 完全可见 | 低 | 高 | 合同要求时唯一诚实选项 |

### 8.3 推荐组合（若必须现场部署且不愿交源码）

1. **合同**：明确「交付物为可运行系统与文档，不含源代码」；禁止反编译、扩散；违约责任。  
2. **架构**：  
   - 业务后台可现场部署；  
   - **Ollama 模型调用 / 规则引擎 / 报告核心**若高度敏感，可改为我方内网 API（现场 Django 只做编排）——甲方更难拿到算法细节。  
3. **交付物**：  
   - 硬盘加密的虚机或 Docker 镜像；  
   - 镜像用户无 `sudo`、无 docker 导出权限（现实中甲方机房管理员往往有，需书面约束）；  
   - 不附 `.git`、不附 `docs` 中内部设计稿（可另附《用户手册》）。  
4. **技术加壳（可选）**：对 `apps/api/inspection_report_make.py`、`utils/frontend_schema_rule_engine.py` 等大块逻辑做 Nuitka 编译，其余保留可热修配置。  
5. **运营**：补丁由我方出镜像版本；甲方不自行改代码。

### 8.4 即使「藏源码」也藏不住的部分

- 浏览器里的页面结构、接口路径与字段（抓包即得）。  
- PDF 模板、业务 JSON 模板（本就在 `media/file_library/templates`，属业务资产，通常**需要**交给甲方使用）。  
- 数据库结构（可通过 Admin/迁移痕迹推断）。  

因此「源码保护」应聚焦 **Python 业务逻辑与管线实现**，不要承诺「甲方完全无法了解系统如何工作」。

### 8.5 不建议对甲方承诺的说法

- 「编译后 100% 无法逆向」  
- 「给了服务器但绝对拿不到任何逻辑」  
- 「只靠 PyArmor 即可替代合同与托管」
